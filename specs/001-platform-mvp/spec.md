# 功能规格说明：Platform MVP Foundation（一体化平台基线）

**功能分支**：`001-platform-mvp`

**创建日期**：2026-07-30

**状态**：草稿

**输入**：用户描述："该项目需求总览请参考 docs/requirements/00-总览与导航.md 文档"

> **范围说明**：本规格覆盖 `sca-fullstack-lab` 一体化智能管理平台的最小可行基线（MVP），聚焦于让"管理员登录一次即可使用核心子系统、公开访客可浏览门户"这一首要用户旅程。监控、工作流、AI、消息、检索、文件、定时任务、报表等扩展能力不在本规格内，将在各自独立的 `/speckit-specify` 流程中定义。

## Clarifications

### Session 2026-07-30

- Q: 平台 v1 MVP 的数据规模与增长预期是哪一档？ → A: 中规模企业数据（≤1 万用户、≤100 万日志/日、保留 1 年；日志表启用按月分表但不分库）。
- Q: 角色"数据范围"（数据权限）的执行模型应采用哪一套？ → A: 五级经典模型（全部 / 本部门及以下 / 仅本部门 / 仅本人 / 自定义部门集合），通过 Mapper 拦截器拼接 SQL `IN` 子查询。
- Q: 用户账号的生命周期状态机应采用哪一版？ → A: 标准五态（待激活 / 正常 / 禁用 / 锁定 / 已删除(软删除)）。
- Q: 多管理员并发编辑同一资源时的冲突处理策略应采用哪一种？ → A: 乐观锁 + 关键资源分布式锁组合（实体加 `version` + MyBatis-Plus `@Version` 拦截器，冲突返回 409；菜单树/角色权限批量分配等关键写操作额外用 Redisson `@DistributedLock`）。
- Q: 公开内容（博客/新闻/产品介绍）的发布工作流状态机应采用哪一版？ → A: 标准四态（草稿 / 待审核 / 已发布 / 已下架）。

## 用户场景与测试 *（必填）*

### 用户故事 1 - 超级管理员登录与基础系统管理 （优先级：P1）

作为超级管理员，我希望在一体化平台输入账号、密码与图形验证码登录后，进入工作台首页并完成菜单、角色、用户、部门、字典、参数、通知等基础系统管理，以便把平台"地基"搭起来，为后续子系统提供账号、权限、字典等共享数据。

**为何此优先级**：登录与系统管理是所有其他子系统的依赖前置；没有这一层，后续工作流审批、AI 助手、监控大盘等都无法以受控方式访问。它是实现路线图第 1–2 周的"项目骨架 + 单体 CRUD + 登录 + RBAC"。

**独立测试**：通过"创建一个角色 → 给角色分配菜单权限 → 创建一个用户并绑定该角色 → 用新用户登录并仅能看到对应菜单"这一闭环即可完整测试，并交付一个可演示的"管理员 + 受限用户"双账号体系。

**验收场景**：

1. **给定** 数据库中尚无任何管理员账号，**当** 系统首次启动时，**那么** 自动初始化一个超级管理员账号（默认账号与初始密码可改），并强制首次登录修改密码。
2. **给定** 超级管理员已在登录页输入正确账号、密码与图形验证码，**当** 提交登录，**那么** 进入工作台首页，看到统计卡片与待办列表，且会话在浏览器关闭后仍可在配置的"记住我"周期内保持。
3. **给定** 超级管理员已登录，**当** 在系统管理菜单中创建一个新角色并勾选若干菜单与按钮权限，**那么** 该角色立即可被分配给用户，且分配后该用户登录只能看到对应菜单。
4. **给定** 超级管理员已登录，**当** 在用户管理中禁用某普通用户账号，**那么** 该用户下次登录被拒绝，且其已存在的会话被立即失效。
5. **给定** 超级管理员已登录，**当** 连续 5 次输入错误密码尝试登录某普通账号，**那么** 该账号被锁定 15 分钟，并记录到登录日志。

### 用户故事 2 - 单点登录与单点注销（SSO / SLO） （优先级：P2）

作为管理员，我希望在一体化平台登录一次后，访问工作流、AI 助手、报表等任何子系统时都无需再次登录；当我登出或会话过期时，所有子系统同步下线；当我的账号被管理员踢下线时，所有正在使用的子系统页面立即跳回一体化登录中心。

**为何此优先级**：SSO 是一体化平台相对"子系统拼盘"的核心差异化价值；没有 SSO 的"一体化"只是 UI 上的拼接。它是实现路线图第 3–4 周的"拆微服务 + 网关 + SSO + 踢人下线"。

**独立测试**：通过"在一体化平台登录 → 在新标签打开子系统 A → 看到免登直接进入 → 在一体化平台点登出 → 子系统 A 页面下次操作即跳回登录中心"这一闭环即可完整测试，并交付一个真正"一次登录、处处可用"的体验。

**验收场景**：

1. **给定** 管理员已在一体化平台登录，**当** 在新浏览器标签访问任意子系统的受保护页面，**那么** 无需再次登录直接进入该页面，端到端跳转延迟不超过 2 秒。
2. **给定** 管理员已在一体化平台登录并打开了多个子系统标签，**当** 在一体化平台点击"退出登录"，**那么** 所有子系统标签在下一次交互时跳回一体化登录中心。
3. **给定** 管理员正在使用子系统 A，**当** 另一位超级管理员在系统管理中将该管理员"踢下线"，**那么** 子系统 A 的页面在 5 秒内自动跳回一体化登录中心，并给出"您的账号已在其他地点登录/被管理员下线"提示。
4. **给定** 管理员的会话已过期（默认 30 分钟无操作），**当** 在子系统页面发起任意请求，**那么** 被网关拦截并跳回一体化登录中心，登录成功后回到原子系统页面。
5. **给定** 一位第三方合作方持有效 OAuth2 凭证，**当** 调用授权端点，**那么** 系统按 OAuth2 流程签发访问令牌，使其可代表已授权用户调用受保护接口（不暴露管理员密码）。

### 用户故事 3 - 公开访客浏览门户 （优先级：P3）

作为未登录的公开访客，我希望在浏览器中访问门户首页，浏览博客、新闻、产品介绍等公开内容，无需任何登录，且页面加载迅速、被搜索引擎友好收录、对我所在的地理位置与语言友好。

**为何此优先级**：公开门户是对外形象与 SEO/GEO 入口；它不依赖管理员体系，可独立开发与部署，且为学习 SSG 预渲染、SEO、CDN 缓存等前端工程能力提供真实载体。它是实现路线图第 11 周的内容，但作为公开访客的唯一入口，规格基线在此一并定义。

**独立测试**：通过"未登录访问门户首页 → 进入一篇博客详情 → 在浏览器禁用 JS 仍能看到主要内容 → 搜索引擎模拟抓取返回完整 HTML"这一闭环即可完整测试，并交付一个真正面向公开访客的子站。

**验收场景**：

1. **给定** 公开访客未登录，**当** 访问门户首页，**那么** 首屏内容在 1 秒内呈现，且无需登录即可浏览博客、新闻、产品介绍列表。
2. **给定** 公开访客进入了某篇博客详情页，**当** 在浏览器中禁用 JavaScript 后刷新，**那么** 仍能看到完整的博客正文内容（即内容为预渲染或服务端渲染）。
3. **给定** 搜索引擎爬虫抓取门户博客详情页，**当** 解析返回的 HTML，**那么** 包含完整的标题、正文、meta 描述、Open Graph 标签，且 Lighthouse SEO 评分 ≥ 90。
4. **给定** 公开访客的浏览器首选语言为英文/地理位置为海外，**当** 访问门户，**那么** 内容按访客语言与地理位置呈现对应版本（GEO 友好）。
5. **给定** 公开访客在门户浏览，**当** 切换到 admin 子站链接，**那么** 跳转到一体化登录中心，且不会因未登录而暴露任何管理员数据。

### 用户故事 4 - 操作审计与登录日志 （优先级：P3）

作为超级管理员，我希望系统自动记录所有写操作（谁、何时、在哪个模块、做了什么、关键入参、来源 IP、耗时）以及所有登录相关事件（登录成功、登录失败、登出、踢人下线），以便在安全事故或合规审计时可以追溯。

**为何此优先级**：企业级平台的合规底线；没有审计就没有"事后可查"。它也是后续学习"操作日志如何用 MQ 异步落盘 + ES 检索"的载体。它是实现路线图第 1–2 周即需具备的横切能力。

**独立测试**：通过"在系统管理中禁用某用户 → 进入操作日志查询页 → 看到该操作的完整记录（操作人、时间、模块、入参、IP）"这一闭环即可完整测试，并交付一个可查询的审计日志页面。

**验收场景**：

1. **给定** 超级管理员已登录，**当** 在系统管理中执行任何写操作（新增、修改、删除、启停、踢人下线），**那么** 系统异步记录一条操作日志，包含操作人、时间、模块、操作类型、关键入参（敏感字段脱敏）、来源 IP、耗时。
2. **给定** 任意用户尝试登录，**当** 提交登录表单，**那么** 无论成功或失败都记录一条登录日志，包含账号、时间、IP、地理位置（IP 反查）、浏览器、操作系统、登录结果、失败原因。
3. **给定** 超级管理员已登录，**当** 在操作日志查询页按"操作人 / 时间范围 / 模块 / 操作类型"组合检索，**那么** 返回分页结果并可下钻查看单条记录详情。
4. **给定** 超级管理员已登录，**当** 在登录日志查询页按"账号 / 时间范围 / 登录结果"组合检索，**那么** 返回分页结果，且能从某条失败登录快速跳转到同账号的所有登录尝试。
5. **给定** 审计日志中的密码、身份证号、手机号、Token 等敏感字段，**当** 查看日志详情，**那么** 全部以脱敏形式呈现（如 `138****8888`），且无法通过任何接口还原原值。

### 边界情况

- 当数据库连接出现抖动时，登录请求是否会被限流而不是直接报 500？
- 当验证码服务自身不可用时，登录是降级为免验证码还是直接拒绝登录？默认拒绝，以避免暴力破解。
- 当 SSO 令牌签发服务不可用时，子系统是否应该返回友好的"登录服务暂不可用"页面而不是技术性 500？是。
- 当公开门户的某篇博客正文包含跨站脚本（XSS） payload 时，系统是否在渲染前清洗？是，富文本入口必须清洗。
- 当管理员账号被自己禁用自己时，系统是否允许？不允许，必须保留至少一个活跃超级管理员。
- 当踢人下线操作目标是自己时，系统是否允许？不允许，必须给出明确提示。
- 当审计日志写入失败时（如 MQ 不可用），主业务是否回滚？不回滚，但必须有本地兜底落盘与告警。
- 当访客在门户发起高频抓取时，是否触发限流？是，按 IP 限流。
- 当两位管理员同时编辑同一角色（A 改权限点、B 改数据范围）时，系统如何处理？后者提交时触发乐观锁冲突，返回 409，前端提示"该资源已被他人修改，是否刷新后重试"，避免覆盖前者的修改。

## 需求 *（必填）*

### 功能需求

**认证与登录**

- **FR-001**：系统必须允许管理员通过"账号 + 密码 + 图形验证码"登录一体化平台，并支持"记住我"可配置周期。
- **FR-002**：系统必须支持会话过期策略可配置；会话过期后任意子系统的下次请求自动引导回一体化登录中心。
- **FR-003**：系统必须支持连续登录失败 N 次后锁定账号 M 分钟（N、M 可配置，默认 5 次与 15 分钟）。
- **FR-004**：系统必须支持"踢人下线"能力，管理员可强制让某用户立即下线，且其所有子系统会话在 5 秒内失效。

**单点登录与注销**

- **FR-005**：系统必须支持单点登录（SSO）——在一体化平台登录后，访问任何子系统时无需再次登录，端到端跳转延迟 ≤ 2 秒。
- **FR-006**：系统必须支持单点注销（SLO）——在一体化平台登出后，所有子系统同步下线。
- **FR-007**：系统必须支持 OAuth2 授权端点，允许第三方合作方持有效凭证代表已授权用户访问受保护接口。
- **FR-008**：系统必须保证登录态过期、被踢下线、未登录三种情况在子系统的表现一致——下次操作即跳回一体化登录中心，登录成功后回到原页面。

**权限与系统管理**

- **FR-009**：系统必须支持基于角色的访问控制（RBAC），采用"用户—角色—权限点"三级模型，权限点可挂载到菜单与按钮。
- **FR-010**：系统必须提供系统管理的全功能 CRUD：用户、角色、菜单、部门、字典、参数、通知。
- **FR-011**：系统必须保证新建角色与权限变更对已登录用户在下一次请求或刷新后立即生效，不需要重新登录。
- **FR-012**：系统必须保证至少保留一个活跃超级管理员，禁止任何操作导致"无超级管理员可登录"的状态。
- **FR-025**：系统必须支持五级数据权限模型——全部 / 本部门及以下 / 仅本部门 / 仅本人 / 自定义部门集合，由角色配置；业务列表查询通过 Mapper 拦截器自动拼接 SQL `IN` 子查询（按 `dept_id` 或 `creator` 维度），同一接口对不同角色返回不同可见数据集。
- **FR-026**：系统必须采用五态用户账号生命周期——待激活 / 正常 / 禁用 / 锁定 / 已删除（软删除）；状态迁移规则：待激活→正常（首次登录或管理员审核通过）、正常→禁用（管理员手动）、正常→锁定（连续登录失败 N 次自动触发）、锁定→正常（超时自动或管理员手动）、任何态→已删除（软删除，仅超级管理员可执行且不可删除最后一个超管）；列表查询默认排除"已删除"；登录时按状态返回不同拒绝提示文案。

**网关与统一契约**

- **FR-013**：所有外部请求必须经过统一网关进行鉴权、限流、跨域处理后再转发到对应业务服务，禁止客户端直连业务服务端口。
- **FR-014**：系统对外接口必须采用统一响应格式，包含业务码、消息、数据、时间戳四个字段；业务错误不得使用 HTTP 200 包装。
- **FR-015**：系统必须按统一规范设计资源路径与 HTTP 方法语义：查询用 GET、新增用 POST、全量更新用 PUT、部分更新用 PATCH、删除用 DELETE；禁止用 GET 执行写操作。

**公开门户**

- **FR-016**：系统必须为公开访客提供无需登录的门户，包含博客、新闻、产品介绍三类内容列表与详情。
- **FR-017**：公开门户内容必须支持搜索引擎友好（SEO）与多语言地理友好（GEO）的预渲染，禁用 JavaScript 后仍可见正文。
- **FR-018**：公开门户的博客、新闻详情页必须包含完整的 meta 描述、Open Graph 标签，Lighthouse SEO 评分 ≥ 90。
- **FR-029**：系统必须对公开内容采用四态发布工作流——草稿 / 待审核 / 已发布 / 已下架；普通员工起草后提交进入"待审核"，业务审批人审核通过后转为"已发布"并被 SEO 索引与门户列表可见，超级管理员可"下架"使其不再公开但保留审计记录；只有"已发布"内容出现在公开门户的列表与详情中，非"已发布"内容返回 410 Gone（已下架）或 404（不存在）以让爬虫从索引中移除。

**审计与日志**

- **FR-019**：系统必须记录所有写操作的审计日志，含操作人、时间、模块、操作类型、关键入参（敏感字段脱敏）、来源 IP、耗时。
- **FR-020**：系统必须记录登录、登出、踢人下线、登录失败的登录日志，含账号、时间、IP、地理位置、浏览器、操作系统、结果与失败原因。
- **FR-021**：审计与登录日志必须支持按多条件组合检索与分页，并支持从某条日志快速跳转到同账号/同模块的相关记录。
- **FR-022**：审计日志中的密码、Token、身份证号、手机号等敏感字段必须以脱敏形式呈现，且无法通过任何接口还原原值。
- **FR-024**：操作日志与登录日志必须保留至少 1 年；按月分表（不分库），1 年前的数据归档至冷存表，归档表仍可查询（P95 查询响应 ≤ 3 秒）。

**数据兼容**

- **FR-023**：系统必须同时兼容多种主流关系型数据库——默认使用 MySQL，同时通过适配层兼容人大金仓 KingbaseES 与达梦 DM8，业务代码无需为不同数据库编写分支。

**并发与一致性**

- **FR-027**：系统必须对管理员可编辑实体（用户、角色、菜单、部门、字典、参数、通知、公开内容）采用乐观锁——实体表加 `version` 字段，Mapper 层通过乐观锁拦截器在更新冲突时返回 409；前端收到 409 后提示"该资源已被他人修改，是否刷新后重试"。
- **FR-028**：菜单树编辑、角色权限批量分配、字典批量刷新等关键写操作必须在 Service 层使用分布式锁（基于 Redisson，锁 Key 含资源类型与资源 ID，默认 TTL 30 秒），避免并发覆盖；锁超时后自动释放。

### 关键实体 *（功能涉及数据时必填）*

- **用户（User）**：代表一个可登录的账号；关键属性有账号、姓名、邮箱、手机、状态（五态：待激活 / 正常 / 禁用 / 锁定 / 已删除(软删除)）、所属部门、角色集合；与角色多对多、与部门多对一。
- **角色（Role）**：代表一类权限集合；关键属性有角色码、名称、数据范围（五级：全部 / 本部门及以下 / 仅本部门 / 仅本人 / 自定义部门集合）、权限点集合；与用户多对多、与权限点一对多。
- **菜单（Menu）**：代表前端可访问的菜单项与对应路由；树形结构，每个节点可挂载权限标识；与角色多对多。
- **部门（Department）**：代表组织结构节点；树形结构，含负责人；与用户一对多。
- **字典（Dictionary）**：代表枚举常量集合；按"类型 + 编码"唯一索引，含名称与排序。
- **参数（Parameter）**：代表系统级可热更新的键值配置；按"键"唯一索引，含类型与说明。
- **通知（Notice）**：代表面向管理员的通知公告；含标题、富文本内容、类型、状态、发布时间。
- **公开内容（Portal Content）**：代表门户的博客、新闻、产品介绍；含标题、正文、分类、标签、SEO meta、发布时间、状态（四态：草稿 / 待审核 / 已发布 / 已下架）、作者、审核人。
- **操作日志（OperationLog）**：代表一次写操作审计记录；含操作人、模块、操作类型、关键入参（脱敏）、来源 IP、耗时、时间戳。
- **登录日志（LoginLog）**：代表一次登录相关事件；含账号、时间、IP、地理位置、浏览器、操作系统、结果、失败原因。

## 成功标准 *（必填）*

### 可衡量结果

- **SC-001**：管理员可在 30 秒内完成登录（含输入验证码）并进入工作台首页。
- **SC-002**：单点登录跳转的端到端延迟 ≤ 2 秒（从子系统触发访问到完成免登进入页面）。
- **SC-003**：系统支撑 500 并发管理员在线使用不降级，登录、查询、写操作 P95 响应时间 ≤ 1 秒。
- **SC-004**：公开门户首屏内容在 1 秒内呈现给访客（预渲染 + 静态托管）。
- **SC-005**：公开门户的博客/新闻页面被主流搜索引擎收录，Lighthouse SEO 评分 ≥ 90。
- **SC-006**：90% 的管理员首次使用即可在无文档辅助下独立完成"创建用户 → 分配角色 → 配置菜单 → 新用户登录验证权限"全流程。
- **SC-007**：所有写操作 100% 留下可追溯的审计记录；查询任意一条审计记录从触发到结果呈现 ≤ 1 秒。

## 假设

- **技术栈假设**：复用项目宪法（`.specify/memory/constitution.md`）已锁定的技术栈基线——后端 Spring Cloud Alibaba + Sa-Token + MyBatis-Plus + Redis/Redisson + RabbitMQ；前端 Vue3 + TypeScript + Naive UI + Pinia + Vite。规格本身保持技术中立，但实现阶段以此栈为准。
- **MVP 范围假设**：v1 MVP 聚焦实现路线图前 4 周——项目骨架 + 单体 CRUD（用户/角色/菜单/字典/参数/通知/部门）+ 登录 + RBAC + 拆微服务 + 网关 + SSO + 踢人下线 + 公开门户基线 + 审计日志。监控、工作流、AI、消息推送、全文检索、文件管理、定时任务、低代码报表、分库分表、国产化深度适配等扩展能力在 MVP 之后按路线图分批交付，各自走独立 `/speckit-specify`。
- **数据库假设**：v1 主选 MySQL 8.4 LTS 作为业务主库；KingbaseES 与 DM8 通过 ShardingSphere 适配层兼容，业务代码不写方言分支。
- **数据规模假设**：v1 MVP 目标规模为"中规模企业数据"——≤1 万用户、≤100 万日志/日、日志保留 1 年；操作/登录日志表按月分表（ShardingSphere 精确分片，不分库），1 年前数据归档至冷存表。该规模决定分表策略在第 12 周启用，但日志表的分表字段（按 `create_time` 月份）必须在第 1–2 周建表时即确定，避免后期迁移。
- **SSO 主路径假设**：SSO 主路径采用 Sa-Token 内建 SSO（同域免登 + 跨域 Ticket 模式）；OAuth2 Server 用于第三方合作方接入，不作为管理员登录主路径。
- **门户渲染假设**：公开门户前端采用 Vite SSG 预渲染 + Nginx 静态托管，内容由独立的后台接口提供；GEO 友好通过 CDN 边缘节点 + 多语言文案实现。
- **部署假设**：先单节点开发环境（Nacos 注册中心已就绪），后扩展为多节点集群；规格不约束部署拓扑。
- **用户环境假设**：用户具备稳定的网络连接，浏览器为现代版 Chrome / Edge / Safari；不兼容 IE。
- **依赖假设**：依赖项目宪法已声明的版本基线（Spring Boot 3.5.0、Spring Cloud 2025.0.0、Spring Cloud Alibaba 2025.0.0、Sa-Token 1.44.0 等），后续 `/speckit-plan` 阶段会基于最新官方文档交叉验证。
