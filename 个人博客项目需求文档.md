## 1. 项目概述

### 1.1 项目定位

一个 **多用户个人博客平台**，作为全栈学习项目，覆盖微服务架构的完整技术栈。采用 **前后端分离 + 微服务架构**，以 Spring Cloud Alibaba 全家桶为核心。

### 1.2 核心功能清单

| 模块         | 功能点                                                              | 优先级 |
| ------------ |------------------------------------------------------------------| :----: |
| **用户系统** | 注册/登录、SA-Token 认证、邮箱/手机号/微信 OAuth2 登录、RBAC 权限（USER/AUTHOR/ADMIN） |   P0   |
| **博客系统** | 发布/编辑/删除博客、Markdown 编辑器、草稿/发布状态、分类/标签、图片上传                       |   P0   |
| **评论系统** | 发表评论、嵌套回复（二级）、评论审核、敏感词过滤                                         |   P0   |
| **互动系统** | 点赞（博客/评论）、收藏博客                                                   |   P1   |
| **搜索系统** | Elasticsearch 全文检索、搜索建议、高亮显示                                     |   P1   |
| **RSS**      | RSS 2.0 订阅源                                                      |   P2   |
| **后台管理** | 用户管理、博客审核、评论审核、数据统计面板                                            |   P1   |

### 1.3 非功能性需求

- 接口响应时间 P99 < 500ms（普通查询，缓存命中后 < 50ms）
- 支持水平扩展（微服务无状态 + Nacos 注册 + Dubbo 软负载）
- 缓存策略：Redis 多级缓存（热点文章详情、用户信息、分类标签列表）
- 读写分离：MySQL 主从复制 + ShardingSphere-JDBC 读写分离
- 容器化部署：Docker Compose 一键启动全部服务

## 2. 关键技术决策深度分析

> 这一节是本文档的核心——**每个技术选择都有明确的原因**，不只是列清单。

### 2.1 认证授权：SA-Token ← 替代 Spring Security

**选择理由（四层论证）：**

**第一层：复杂度对比**

```java
// ========== Spring Security 实现登录接口 ==========
// 需要：SecurityConfig、JwtAuthenticationFilter、UserDetailsServiceImpl、
//       AuthenticationEntryPoint、JwtTokenProvider... 至少 5-6 个类

// ========== SA-Token 实现登录接口 ==========
@RestController
public class AuthController {
    @PostMapping("/login")
    public R<?> login(@RequestBody LoginDTO dto) {
        // 1. 校验账号密码
        User user = userService.login(dto.getUsername(), dto.getPassword());
        // 2. 一行代码完成登录（自动生成 Token 并存入 Redis）
        StpUtil.login(user.getId());
        // 3. 返回 Token 信息
        return R.ok(SaTokenInfoBuilder.build(StpUtil.getTokenInfo()));
    }
}
```

**第二层：鉴权方式对比**

```java
// Spring Security：需要配置 SecurityFilterChain + 方法级 @PreAuthorize
// SA-Token：纯注解驱动
@SaCheckLogin                          // 必须登录
@SaCheckRole("ADMIN")                  // 必须 ADMIN 角色
@SaCheckPermission("article:delete")   // 必须拥有指定权限
@SaCheckRoleOr("ADMIN", "AUTHOR")      // 满足任一角色
```

**第三层：与 Dubbo 集成**

```java
// SA-Token 官方提供 sa-token-dubbo 插件
// Dubbo Provider 端自动解析调用方传递的 Token，还原登录态
// 无需手动传递 Header，零侵入
```

**第四层：OAuth2 第三方登录**

```yaml
# SA-Token OAuth2 配置（application.yml）
sa-token:
  oauth2:
    github:
      client-id: xxx
      client-secret: xxx
      redirect-uri: http://localhost:8080/api/auth/oauth2/github/callback
```

**一句话总结**：SA-Token 用 Spring Security 1/5 的代码量覆盖博客系统 100% 的认证需求。

### 2.2 服务间调用：Apache Dubbo ← 替代 OpenFeign

**选择理由：**

```
┌─────────────────────────────────────────────────────────────┐
│                    OpenFeign 调用路径                         │
│                                                             │
│  article-svc ──HTTP/1.1+JSON──▶ Gateway? ──HTTP──▶ search-svc│
│       │                            │                        │
│       └── 需要 Spring Cloud LoadBalancer 做客户端负载均衡 ──┘ │
│                                                             │
│  问题：                                                      │
│  1. HTTP 三次握手 + JSON 序列化，每次调用开销大               │
│  2. LoadBalancer 是 HTTP 层负载均衡，粒度粗                  │
│  3. JSON 序列化的冗余文本传输（字段名重复）                   │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│                      Dubbo 调用路径                          │
│                                                             │
│  article-svc ──Triple(HTTP/2+Protobuf)──▶ search-svc        │
│       │                            │                        │
│       └── Dubbo 内置负载均衡（LeastActive/ConsistentHash）──┘ │
│                                                             │
│  优势：                                                      │
│  1. 长连接复用，无握手开销                                   │
│  2. Protobuf 二进制序列化，体积比 JSON 小 3-10 倍            │
│  3. 内置多种负载均衡策略，无需额外组件                       │
│  4. 天然集成 Nacos 注册发现 + Sentinel 熔断                  │
└─────────────────────────────────────────────────────────────┘
```

**Dubbo 配置示例：**

```yaml
# 服务提供者（如 search-svc）
dubbo:
  application:
    name: blog-search
  registry:
    address: nacos://localhost:8848
  protocol:
    name: tri          # Triple 协议（HTTP/2 + Protobuf）
    port: -1           # 复用 Spring Boot HTTP 端口
  scan:
    base-packages: com.blog.search.rpc  # Dubbo Service 实现类扫描路径

# 服务消费者（如 article-svc）
dubbo:
  application:
    name: blog-article
  registry:
    address: nacos://localhost:8848
  consumer:
    check: false       # 启动时不检查提供者是否存在
```

### 2.3 负载均衡：Dubbo 内置 ← 替代 Spring Cloud LoadBalancer

**不需要 Spring Cloud LoadBalancer 的原因：**

| 调用链路                   |                       负载均衡由谁负责                       |
| -------------------------- | :----------------------------------------------------------: |
| 浏览器 → Nginx             |               Nginx upstream（反向代理层 LB）                |
| Nginx → Gateway            |                        Nginx upstream                        |
| Gateway → 微服务 HTTP 接口 |               Nacos 服务发现 + Gateway 内置 LB               |
| 微服务间 Dubbo RPC         | **Dubbo 内置 LB**（Random/RoundRobin/LeastActive/ConsistentHash） |

Spring Cloud LoadBalancer 只服务于 `RestTemplate` / `OpenFeign` 的 **HTTP 客户端调用**。Dubbo RPC 不经过 HTTP 客户端，LoadBalancer 无法介入，也无需介入。

---

### 2.4 分布式事务：不引入 Seata，采用最终一致性

**博客系统跨服务操作的最终一致性方案：**

```
场景：文章发布 → 同步 Elasticsearch 索引
─────────────────────────────────────────

主流程（同步）：
  article-svc ──Dubbo RPC──▶ search-svc.createIndex(article)
       │                           │
       │                           ├── 成功 → 结束
       │                           └── 失败 → 记录到本地消息表
       │
       └── 事务提交，文章状态 = PUBLISHED

补偿流程（异步）：
  XXL-Job 定时任务（每分钟）
    └── 扫描本地消息表（status=PENDING）
        └── 重试 Dubbo RPC（最多 3 次）
            ├── 成功 → 标记 COMPLETED
            └── 3次失败 → 标记 FAILED，发送告警

兜底流程：
  XXL-Job 每日凌晨全量同步
    └── SELECT * FROM t_article WHERE status='PUBLISHED'
        └── 批量写入 ES（幂等，基于 article_id 覆盖）
```

**为什么不用 Seata：**

1. 博客系统无「资金/库存」级别的强一致性要求
2. Seata AT 模式需要额外部署 Seata Server + 每个数据库添加 `undo_log` 表
3. Seata 会引入全局锁，降低并发性能
4. 最终一致性 + 定时补偿 完全满足博客场景

---

### 2.5 消息队列：RocketMQ 标记为可选增强

| 方案                         | 复杂度 | 可靠性 | 推荐场景     |
| ---------------------------- | :----: | :----: | ------------ |
| **A. Dubbo 同步调用 + 重试** |   低   |   中   | MVP 快速上线 |
| **B. RocketMQ 异步解耦**     |   中   |   高   | 生产化部署   |

**推荐策略**：

- Phase 1-5（MVP 阶段）：使用方案 A（Dubbo 同步 + 失败重试 + 定时补偿）
- Phase 7（优化阶段）：将 ES 同步、评论通知等切换为 RocketMQ 异步

---

### 2.6 工作流引擎：不使用 Warm-Flow

博客系统的审核流程是 **单步状态机**：

```
         提交
    PENDING ────────▶ APPROVED（通过）
       │
       └────────────▶ REJECTED（驳回）
```

状态枚举 + 条件判断即可，无需工作流引擎。

---

### 2.7 RESTful API：实用主义 RESTful

**遵循的 RESTful 规范：**

- ✅ 资源 URL 使用名词复数：`/api/articles`、`/api/comments`
- ✅ HTTP 方法语义：GET 查询、POST 创建、PUT 全量更新、PATCH 部分更新、DELETE 删除
- ✅ 状态码语义：200 成功、201 创建成功、400 参数错误、401 未认证、403 无权限、404 不存在、409 冲突
- ✅ 分页参数标准化：`?page=1&size=10&sort=published_at,desc`

**不教条的地方：**

- ✅ `POST /api/articles/{id}/like` — 动词路由表达非 CRUD 动作
- ✅ `POST /api/search` — 复杂查询体不适合放 URL Query
- ✅ `POST /api/admin/articles/batch-audit` — 批量操作
- ✅ 响应体统一包装为 `{ code, message, data }`，不强制 HATEOAS

package com.blog.article.service.impl;

import com.blog.api.search.SearchService;
import org.apache.dubbo.config.annotation.DubboReference;
import org.springframework.stereotype.Service;

@Service
public class ArticleServiceImpl {

    @DubboReference(version = "1.0.0", retries = 2, timeout = 5000)
    private SearchService searchService;

    public void publishArticle(Article article) {
        // 1. 保存到 MySQL
        articleMapper.insert(article);

        // 2. Dubbo RPC 同步 ES（失败由定时任务补偿）
        try {
            searchService.syncArticleIndex(ArticleIndexDTO.from(article));

            // 记录到本地消息表，由 job 服务定时重试
            syncFailedLogService.record(article.getId(), SyncType.ES_INDEX);
        }
    }

### 6.2 SA-Token 使用 Redis 存储，无需额外表

SA-Token 的 Token、登录态、权限等信息全部存储在 Redis，无需创建额外的数据库表。SA-Token 在 Redis 中的 Key 结构（自动管理）：

| Redis Key Pattern                            | 说明                  |
| -------------------------------------------- | --------------------- |
| `Authorization:login:token:{tokenValue}`     | Token → 用户ID 映射   |
| `Authorization:login:id:{userId}`            | 用户ID → 登录设备列表 |
| `Authorization:login:role:{userId}`          | 用户角色信息          |
| `Authorization:login:permission:{userId}`    | 用户权限信息          |
| `Authorization:token-blacklist:{tokenValue}` | Token 黑名单（登出）  |

    public SaReactorFilter saReactorFilter() {
        return new SaReactorFilter()
            // 拦截所有 /api/** 请求
            .addInclude("/api/**")
            // 排除登录注册等公开接口
            .addExclude(
                "/api/auth/login",
                "/api/auth/register",
                "/api/auth/oauth2/**",
                "/api/articles/**",   // GET 公开可读
                "/api/search/**",
                "/api/rss"
            )
            // 认证校验
            .setAuth(obj -> {
                SaRouter.match("/api/**", () -> StpUtil.checkLogin());
                // 管理接口需要 ADMIN 角色
                SaRouter.match("/api/admin/**", () -> StpUtil.checkRole("ADMIN"));
            })
            // 异常处理
            .setError(e -> {
                if (e instanceof NotLoginException) {
                    return R.fail(401, "请先登录");
                }
                if (e instanceof NotRoleException) {
                    return R.fail(403, "权限不足");
                }
                return R.fail(500, "服务器错误");
            });
    }
}

**登录接口实现：**

```java
@RestController
@RequestMapping("/api/auth")
public class AuthController {

    @Autowired
    private UserService userService;

    @PostMapping("/login")
    public R<Map<String, Object>> login(@Valid @RequestBody LoginDTO dto) {
        // 1. 校验账号密码
        User user = userService.authenticate(dto.getUsername(), dto.getPassword());
        if (user == null) {
            return R.fail(400, "用户名或密码错误");
        }
        if (user.getStatus() != 1) {
            return R.fail(403, "账号已被禁用");
        }

        // 2. SA-Token 一键登录
        StpUtil.login(user.getId());

        // 3. 获取 Token 信息
        SaTokenInfo tokenInfo = StpUtil.getTokenInfo();

        // 4. 返回
        Map<String, Object> result = new HashMap<>();
        result.put("tokenName", tokenInfo.getTokenName());
        result.put("tokenValue", tokenInfo.getTokenValue());
        result.put("tokenTimeout", StpUtil.getTokenTimeout());
        result.put("userInfo", UserVO.from(user));
        return R.ok(result);
    }

    @PostMapping("/logout")
    @SaCheckLogin
    public R<Void> logout() {
        StpUtil.logout(); // Token 自动加入黑名单
        return R.ok();
    }
}

5. 其余功能：首页文章列表、文章详情、Markdown编辑器(v-md-editor)、
   评论嵌套组件、搜索页、管理后台(仪表盘+审核+用户管理)
```
