# 数据编码与乱码巡检手册

> 2026-08-03 中文乱码修复（变更 `fix-chinese-garbled-text`）后沉淀的巡检清单。
> 背景：MySQL 全链路曾出现 UTF-8 → Latin-1 双重编码乱码（如 `æœ¬æ–‡...`），根因是外部工具/客户端以 latin1 连接写入，修复方案见 `scripts/fix-mojibake.sql`。

## 1. 五级字符集检查

```sql
-- 服务器级
SHOW VARIABLES LIKE 'character_set_server';
-- 连接级（应用 JDBC 连接执行，应返回 utf8mb4）
SHOW VARIABLES LIKE 'character_set_connection';
-- 库级
SELECT DEFAULT_CHARACTER_SET_NAME FROM information_schema.SCHEMATA WHERE SCHEMA_NAME='sca_system';
-- 表级
SELECT TABLE_NAME, TABLE_COLLATION FROM information_schema.TABLES WHERE TABLE_SCHEMA='sca_system';
-- 列级（抽查中文列）
SELECT COLUMN_NAME, CHARACTER_SET_NAME FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA='sca_system' AND TABLE_NAME='t_article' AND DATA_TYPE IN ('varchar','text','mediumtext');
```

验收标准：全部为 `utf8mb4`（表级 `utf8mb4_unicode_ci`）。

## 2. 乱码数据检测

乱码特征字符为 latin1 解码 UTF-8 的典型结果（`æ`/`å`/`ä`/`é` 等），按表检测：

```sql
-- 文章（标题/摘要/正文）
SELECT COUNT(*) FROM t_article
WHERE CONCAT_WS(' ', title, summary, content_md) REGEXP '[æåä]';
-- 门户内容（标题/正文/摘要/SEO 字段）
SELECT COUNT(*) FROM portal_content
WHERE CONCAT_WS(' ', title, body, summary, seo_title, seo_description) REGEXP '[æåä]';
-- 系统表（角色/字典/用户等中文列）
SELECT COUNT(*) FROM sys_role WHERE CONCAT_WS(' ', role_code, role_name, remark) REGEXP '[æåä]';
SELECT COUNT(*) FROM sys_dict WHERE CONCAT_WS(' ', dict_type, dict_label, dict_value) REGEXP '[æåä]';
SELECT COUNT(*) FROM sys_user WHERE nickname REGEXP '[æåä]';
SELECT COUNT(*) FROM sys_dept WHERE CONCAT_WS(' ', dept_name, leader) REGEXP '[æåä]';
SELECT COUNT(*) FROM sys_menu WHERE CONCAT_WS(' ', menu_name, path, component) REGEXP '[æåä]';
SELECT COUNT(*) FROM sys_notice WHERE CONCAT_WS(' ', notice_title, notice_content) REGEXP '[æåä]';
SELECT COUNT(*) FROM sys_param WHERE CONCAT_WS(' ', param_key, param_value, remark) REGEXP '[æåä]';
SELECT COUNT(*) FROM sys_oauth2_client WHERE CONCAT_WS(' ', client_name, client_id) REGEXP '[æåä]';
```

验收标准：全部为 0。

## 3. 双重编码判定

命中乱码的行可用 HEX 判定是否双重编码（可修复）而非其他损坏：

```sql
-- 双重编码特征：utf8mb4 字节为 C3A5/C2BE/C2AE 模式（latin1 字符的 utf8mb4 编码）
SELECT id, LEFT(HEX(title), 40) FROM t_article WHERE title REGEXP '[æåä]';
-- 对照：正确中文 "微" 的 utf8mb4 编码为 E5BEAE；双重编码后为 C3A5C2BEC2AE
```

## 4. 连接配置核对

| 检查项 | 命令/位置 | 期望值 |
|--------|-----------|--------|
| auth JDBC URL | `spring-cloud-alibaba/spring-cloud-auth/src/main/resources/application.yml` | `characterEncoding=UTF-8&connectionCollation=utf8mb4_unicode_ci` |
| system JDBC URL | `spring-cloud-alibaba/spring-cloud-services/spring-cloud-system/src/main/resources/application.yml` | 同上 |
| article JDBC URL | `spring-cloud-alibaba/spring-cloud-services/spring-cloud-article/src/main/resources/application.yml` | 同上 |
| Nacos 共享配置 | `spring-cloud-shared.yaml`（dataId） | 若含 `datasource.url` 必须同左（2026-08-03 核对：不含 datasource） |
| 建表脚本 | `docker/compose/init/sql/sca-system-init.sql`、`db/migration/V1.0.0__*.sql` | 每张表带 `DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci` |

> ⚠️ **禁止**用 `characterEncoding=utf8mb4`：MySQL Connector/J 9.x 不接受该值（`Unsupported character encoding 'utf8mb4'`），必须用 `UTF-8` + `connectionCollation=utf8mb4_unicode_ci` 组合。

## 5. 修复存量乱码

```bash
mysql -uroot -p --default-character-set=utf8mb4 sca_system < scripts/fix-mojibake.sql
```

要点（勿忘）：
- **必须**用 `--default-character-set=utf8mb4` 连接执行，否则修复语句本身会被二次转码
- 脚本含前置基线统计、修复 UPDATE、后置校验三段
- 修复前**必须**备份：`CREATE TABLE <t>_bak_YYYYMMDD AS SELECT * FROM <t>;`
- 回滚：`INSERT INTO <t> SELECT * FROM <t>_bak_YYYYMMDD;`
- 修复表达式 `CONVERT(CAST(CONVERT(col USING latin1) AS BINARY) USING utf8mb4)` 中 `CAST AS BINARY` 不可省略（阻止字符级转换，实现字节还原）

## 6. 预防措施

1. 客户端工具（Navicat/DBeaver/mysql CLI）连接时**必须**显式设置连接字符集为 utf8mb4
2. mysql CLI 手工导数据加 `--default-character-set=utf8mb4`
3. 新服务接入 MySQL 时，JDBC URL 一律 `characterEncoding=utf8mb4`
4. 新增建表脚本一律带显式 `CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci`
