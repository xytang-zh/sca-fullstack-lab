# 06 · 多数据库与多数据源

> 本文详细讲解本项目的 **多数据库场景**、**动态数据源切换**、**国产化适配**、**分库分表** 方案。

---

## 6.1 为什么需要这么多数据库

| 数据库 | 用途 | 理由 |
|--------|------|------|
| **MySQL 8** | 业务主库（用户、角色、菜单、工作流） | 生态最成熟，运维成本最低 |
| **PostgreSQL 16 + pgvector** | RAG 向量库 + 部分业务 | pgvector 是 Spring AI 一等公民，PG 也适合复杂查询 |
| **MongoDB 7** | 对话历史、原始文档、审计日志 | 写入多查询少场景，Schema Free |
| **TDengine 3.3** | 服务器监控指标 | 时序数据写入快、压缩比高、查询性能优 |
| **ElasticSearch 8** | 全文检索、日志 | 倒排索引，全文搜索无可替代 |
| **人大金仓 KingbaseES V8** | 国产化适配 | 兼容 PG 协议，信创要求 |
| **达梦 DM8** | 国产化适配 | 兼容 Oracle 语法，信创要求 |
| **Redis 7** | 缓存、会话、消息 | 通用 |
| **MinIO** | 文件对象存储 | S3 兼容，本地部署 |

---

## 6.2 数据库选型决策树

```
我要存什么数据？
├── 强关系型（用户、订单、流程实例）→ MySQL / KingbaseES / DM
├── 向量（Embedding）→ PostgreSQL + pgvector
├── 文档（对话历史、富文本）→ MongoDB
├── 时序（监控指标）→ TDengine
├── 全文索引（文章、日志）→ ElasticSearch
├── 文件 → MinIO
└── 缓存 → Redis
```

### 6.3.4 进阶：方法级动态切换

```java
public class DataSourceContext {
    private static final ThreadLocal<String> CONTEXT = new ThreadLocal<>();
    public static void set(String ds) { CONTEXT.set(ds); }
    public static String get() { return CONTEXT.get(); }
    public static void clear() { CONTEXT.remove(); }
}

// 在 AOP 切面里根据租户/业务标识动态决定数据源
@Around("@annotation(...)")
public Object around(ProceedingJoinPoint pjp) {
    String tenant = TenantContext.get();
    String ds = "kingbase".equals(tenant) ? "kingbase" : "master";
    DynamicDataSourceContextHolder.push(ds);
    try { return pjp.proceed(); }
    finally { DynamicDataSourceContextHolder.poll(); }
}
```

## 6.4 国产化适配（人大金仓 / 达梦）

### 6.4.1 适配难点

| 难点 | 说明 | 解决方案 |
|------|------|----------|
| SQL 方言 | MySQL 私有函数（GROUP_CONCAT、IFNULL） | 用标准 SQL 重写 |
| 字段类型 | tinyint、datetime 在不同库行为不同 | 用 smallint、timestamp |
| 自增主键 | 不同库实现不同 | 用 MyBatis-Plus 雪花 ID |
| 分页 | MySQL LIMIT、Oracle ROWNUM、PG LIMIT | 用 MP 分页插件（自动适配） |
| 关键字 | user、order、size 等保留字 | 加反引号/双引号，或重命名 |
| 大小写 | PG 默认小写、Oracle 默认大写 | DDL 显式引号 |

### 6.4.2 MyBatis-Plus 多数据库支持

```java
@Configuration
public class MybatisPlusConfig {
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();

        // 多租户
        interceptor.addInnerInterceptor(new TenantLineInnerInterceptor(tenantHandler()));

        // 动态分页（自动识别 DbType）
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor());

        // 数据权限
        interceptor.addInnerInterceptor(new DataPermissionInterceptor());

        return interceptor;
    }

    @Bean
    public IdentifierGenerator identifierGenerator() {
        return new DefaultIdentifierGenerator();  // 雪花 ID
    }
}
```

`PaginationInnerInterceptor` 自动识别 `DbType.MYSQL` / `DbType.KINGBASE_ES` / `DbType.DM` 并生成对应分页 SQL。

### 6.4.4 SQL 兼容性清单

| 场景 | MySQL 写法 | 通用写法（兼容 PG/KingbaseES/DM） |
|------|------------|-----------------------------------|
| 判空 | `IFNULL(a, b)` | `COALESCE(a, b)` |
| 字符串拼接 | `CONCAT(a, b)` | `a || b`（标准 SQL） |
| 日期格式化 | `DATE_FORMAT(t, '%Y-%m-%d')` | `TO_CHAR(t, 'YYYY-MM-DD')` |
| 当前时间 | `NOW()` | `CURRENT_TIMESTAMP` |
| 自增主键 | `AUTO_INCREMENT` | 用 MyBatis-Plus 雪花 ID 替代 |
| 布尔 | `tinyint(1)` | `smallint` + 0/1 |
| 长文本 | `text` / `longtext` | `text`（标准）或 `clob`（Oracle 系） |
| 分页 | `LIMIT 10 OFFSET 0` | 用 MP 分页插件 |

### 6.5.6 分库分表场景（Apache ShardingSphere 5.5.x）

**为什么要分表**：

| 表 | 数据量预估（1 年） | 查询模式 | 是否需要分表 |
|----|---------------------|----------|--------------|
| `sys_user` | 1 万 | 主键查询为主 | ❌ |
| `biz_leave` | 10 万 | 按用户/状态查询 | ❌ |
| `biz_operation_log` | 5000 万+ | 时间范围查询 | ✅ 按月分表 |
| `biz_login_log` | 1000 万+ | 时间范围查询 | ✅ 按月分表 |
| `biz_ai_message` | 1 亿+（AI 对话量） | 按用户+时间 | ✅ 按月分表 |

**集成方式**：

**Step 1：Maven 依赖**

```xml
<dependency>
    <groupId>org.apache.shardingsphere</groupId>
    <artifactId>shardingsphere-jdbc</artifactId>
    <version>5.5.2</version>
</dependency>
```

**Step 2：DataSource 配置**

```properties
# Driver 改为 ShardingSphere
spring.datasource.driver-class-name=org.apache.shardingsphere.driver.ShardingSphereDriver
# YAML 配置位置
spring.datasource.url=jdbc:shardingsphere:classpath:sharding/sharding-config.yaml
```

**Step 3：分片规则 `sharding-config.yaml`**

```yaml
dataSources:
  ds_0:
    dataSourceClassName: com.zaxxer.hikari.HikariDataSource
    driverClassName: com.mysql.cj.jdbc.Driver
    jdbcUrl: jdbc:mysql://127.0.0.1:3306/aurora_log?...
    username: root
    password: xxx

# 分片规则
rules:
  - !SHARDING
    tables:
      # 操作日志：按月分表
      biz_operation_log:
        actualDataNodes: ds_0.biz_operation_log_${202501..202612}
        tableStrategy:
          standard:
            shardingColumn: create_time
            shardingAlgorithmName: log_interval_alg
      biz_login_log:
        actualDataNodes: ds_0.biz_login_log_${202501..202612}
        tableStrategy:
          standard:
            shardingColumn: login_time
            shardingAlgorithmName: log_interval_alg
    shardingAlgorithms:
      log_interval_alg:
        type: INTERVAL
        props:
          # 按月分表
          pattern-prefix: biz_operation_log_
          datetime-pattern: yyyyMM
          datetime-lower: 2025-01-01 00:00:00
          datetime-upper: 2026-12-31 23:59:59
          sharding-suffix-pattern: yyyyMM
          interval-amount: 1
          interval-unit: MONTHS

  - !ENCRYPT
    # 可选：字段加密（如手机号、身份证）
    tables:
      sys_user:
        columns:
          phone:
            cipherColumn: phone_cipher
            plainColumn: phone
            encryptorName: aes_encryptor
    encryptors:
      aes_encryptor:
        type: AES
        props:
          aes-key-value: xxx

props:
  sql-show: true   # 打印分片后的真实 SQL（学习用）
```

**Step 4：MyBatis-Plus 适配**

ShardingSphere-JDBC 是 JDBC 层的增强，对 MyBatis-Plus 透明，但要注意：
- 分片键必须在 SQL 中出现（否则全表扫描）
- 跨分片查询需要聚合（ShardingSphere 自动合并结果）
- 分页插件配合时，`count` 会自动改写为 `count` 各分表后求和

**Step 5：定时建表**

每月初自动创建下个月的分表：

```java
@XxlJob("createNextMonthTables")
public void createNextMonthTables() {
    LocalDate next = LocalDate.now().plusMonths(1);
    String suffix = next.format(DateTimeFormatter.ofPattern("yyyyMM"));
    for (String table : List.of("biz_operation_log", "biz_login_log")) {
        ddlMapper.createLikeTemplate(table, table + "_" + suffix);
        XxlJobHelper.log("已建表: " + table + "_" + suffix);
    }
}
```

**Step 6：历史归档**

```java
@XxlJob("archiveOldLogs")
public void archiveOldLogs() {
    // 6 个月前的日志移到归档库（aurora_archive）
    LocalDate cutoff = LocalDate.now().minusMonths(6);
    archiveMapper.archiveLogsBefore(cutoff);
}
```

**踩坑清单**：

| 坑 | 解决 |
|----|------|
| 查询不带分片键 → 全表扫描 | 强制要求查询条件含 `create_time` |
| 跨分片 JOIN 性能差 | 避免跨分片 JOIN，用绑定表 / 广播表 |
| 分布式事务 | 用本地事务 + Seata AT |
| DDL 操作 | ShardingSphere 不支持自动 DDL，需手动 / 定时建表 |
| 加密字段查询 | 用 `plainColumn` 字段配合 `LIKE`，避免明文检索性能差 |

## 6.6 数据同步方案

### 6.6.1 MySQL → ES（增量同步）

**方案 A：MQ 增量**
```
MySQL 写入 → 触发器 / Binlog → RabbitMQ → aurora-search 消费 → ES 写入
```

**方案 B：Canal 监听 Binlog**
```
MySQL → Canal → MQ → aurora-search → ES
```

学习项目用方案 A 简化：业务代码里写完 MySQL 后，发 MQ 事件。

### 6.6.2 MySQL → ES（全量重建）

```
定时任务（凌晨 2 点）
  → 分页查询 MySQL
  → 批量写入 ES（_bulk API）
  → 重建索引（alias 切换）
```

## 6.7 多级缓存设计

### 6.7.1 架构

```
请求 → Caffeine（L1，本地） → Redis（L2，远程） → MySQL
       │            │              │                │
       └ 5s TTL     └ 5min TTL    └ 永久 / 30d
```

### 6.7.2 实现

```java
@Component
@CacheConfig(cacheNames = "user")
public class UserServiceImpl {

    @LayeredCache(key = "#id", l1Ttl = "5s", l2Ttl = "5m")
    public User getById(Long id) {
        return userMapper.selectById(id);
    }

    @CacheEvict(key = "#user.id")
    public void update(User user) {
        userMapper.updateById(user);
    }
}
```

### 6.7.3 缓存问题对策

| 问题 | 方案 |
|------|------|
| 缓存穿透 | 布隆过滤器 + 空值缓存（短 TTL） |
| 缓存击穿 | 互斥锁（Redisson） / 逻辑过期 |
| 缓存雪崩 | TTL 加随机数 + 多级缓存 |
| 数据一致性 | Cache-Aside + 延迟双删 + MQ binlog |

## 6.8 分布式事务（Seata）

### 6.8.1 何时需要分布式事务

| 场景 | 是否需要 |
|------|----------|
| 同库多表操作 | ❌ 本地事务 |
| 跨库写（MySQL + 国产库） | ✅ Seata AT |
| 微服务调用写多库 | ✅ Seata AT / TCC |
| 跨业务写入 + MQ | ⚪ 本地消息表 / MQ 事务消息 |

### 6.8.2 Seata AT 模式接入
