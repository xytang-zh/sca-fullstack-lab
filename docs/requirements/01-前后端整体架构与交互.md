# 01 · 前后端整体架构与交互

> 本文档定义 **前后端如何通信**、**API 规范**、**SSO 流程**、**WebSocket 协议**、**MQ 事件总线**、**Dubbo RPC**。
> 所有服务在实现接口时**必须**遵守本文档约定。

## 2. RESTful API 强制规范

### 2.1 URI 设计

- 资源名**必须**用复数名词、全小写、短横线分隔：`/api/system/users`、`/api/workflow/instances`
- 路径**必须**包含 `/api/{服务名}/` 前缀，由 Gateway 通过 `StripPrefix=2` 剥离
- 业务动作（非 CRUD）使用动词子资源：`POST /api/system/users/{id}/disable`、`POST /api/workflow/tasks/{id}/approve`
- **禁止**把动词放在路径里：`/getUser`、`/createOrder`、`/deleteUserById`

### 2.2 HTTP 方法语义

| 方法 | 语义 | 是否幂等 | 示例 |
|------|------|----------|------|
| GET | 查询 | ✅ | `GET /api/system/users/{id}` |
| POST | 新增 | ❌ | `POST /api/system/users` |
| PUT | 全量更新 | ✅ | `PUT /api/system/users/{id}` |
| PATCH | 部分更新 | ✅ | `PATCH /api/system/users/{id}/password` |
| DELETE | 删除 | ✅ | `DELETE /api/system/users/{id}` |

### 2.3 统一响应格式

所有 HTTP 接口**必须**返回 `R<T>`：

```json
{
  "code": 200,
  "msg": "success",
  "data": { ... },
  "timestamp": 1722470400000
}
```

| code | HTTP | 含义 |
|------|------|------|
| 200 | 200 | 成功 |
| 400 | 400 | 参数错误 |
| 401 | 401 | 未登录 |
| 403 | 403 | 无权限 |
| 404 | 404 | 资源不存在 |
| 409 | 409 | 资源冲突（如账号已存在） |
| 429 | 429 | 限流 |
| 500 | 500 | 服务器内部错误 |
| 503 | 503 | 服务不可用（熔断） |

> **例外**：OAuth2 `token` 接口遵循 RFC 6749，直接返回 `{"access_token":"xxx","token_type":"Bearer","expires_in":7200}`。

### 2.4 分页规范

入参：
```
GET /api/system/users?pageNum=1&pageSize=10&orderBy=createTime DESC&keyword=admin
```

出参（`PageVO<T>`）：
```json
{
  "code": 200,
  "data": {
    "list": [...],
    "total": 100,
    "pageNum": 1,
    "pageSize": 10,
    "pages": 10
  }
}
```

### 2.5 长整型精度

JavaScript 无法精确表示超过 `2^53` 的数字，雪花 ID（Long）**必须**序列化为 String。

后端配置（在 `spring-cloud-common-web`）：

```java
@JsonComponent
public class LongToStringSerializer extends JsonSerializer<Long> {
    @Override
    public void serialize(Long value, JsonGenerator gen, SerializerProvider sp) {
        gen.writeString(value.toString());
    }
}
```

前端 axios 拦截器自动处理。

### 2.6 链路追踪

- 网关生成 `X-Trace-Id`（UUID），透传到下游
- 下游服务从 `X-Trace-Id` 头读取并打印到 MDC（logback 配置 `%X{traceId}`）
- 前端控制台报错时**必须**展示 `traceId`，方便排查

### 2.7 防重放

敏感接口（如支付、审批）**必须**校验：

```
X-Timestamp: 1722470400000      请求时间（毫秒）
X-Nonce: 6f8a3b2c                随机串
X-Sign: 9a3f...                  HMAC-SHA256(timestamp + nonce + body, secret)
```

服务端校验：timestamp 与当前时间偏差 > 5 分钟拒绝；nonce 在 5 分钟内重复拒绝（Redis 去重）。

## 3. SSO 单点登录完整流程

### 3.1 角色定义

| 角色 | 域名 | 说明 |
|------|------|------|
| SSO Server | `auth.example.com` | 认证中心（spring-cloud-auth） |
| SSO Client A | `admin.example.com` | 一体化管理平台前端 |
| SSO Client B | `flow.example.com` | 工作流子系统前端 |
| SSO Client C | `ai.example.com` | AI 助手子系统前端 |

### 3.2 首次登录时序

```
用户浏览器              Client A (admin)          SSO Server (auth)          Redis
    │                         │                          │                       │
    │  1. 访问 admin/...       │                          │                       │
    │ ──────────────────────▶│                          │                       │
    │                         │  2. 校验本地会话(未登录)  │                       │
    │  3. 302 跳转 auth/sso/login?redirect=admin         │                       │
    │ ◀──────────────────────│                          │                       │
    │  4. GET /sso/auth?redirect=admin                   │                       │
    │ ───────────────────────────────────────────────▶│                       │
    │                         │                          │  5. 校验 Server 会话(未登录)
    │  6. 返回登录页           │                          │                       │
    │ ◀──────────────────────────────────────────────│                       │
    │  7. POST /sso/auth (账号+密码+验证码)             │                       │
    │ ───────────────────────────────────────────────▶│                       │
    │                         │                          │  8. 校验账号密码      │
    │                         │                          │  9. StpUtil.login(10001, deviceId)
    │                         │                          │ ────────────────────▶│ satoken:login:session:10001
    │                         │                          │  10. 生成授权码 code   │
    │  11. 302 跳回 admin/sso/callback?code=xxx          │                       │
    │ ◀──────────────────────────────────────────────│                       │
    │  12. GET /sso/callback?code=xxx                    │                       │
    │ ──────────────────────▶│                          │                       │
    │                         │  13. POST /sso/code2session │                    │
    │                         │ ──────────────────────▶│                       │
    │                         │                          │  14. 校验 code        │
    │                         │                          │  15. 返回 loginId + token
    │                         │ ◀──────────────────────│                       │
    │                         │  16. 保存本地会话        │                       │
    │  17. 重定向回原页面       │                          │                       │
    │ ◀─────────────────────│                          │                       │
```

### 3.3 二次跳转（已登录 Server 端，访问 Client B）

```
用户访问 flow.example.com/apply
  → flow 校验本地会话(未登录)
  → 302 跳转 auth/sso/auth?redirect=flow
  → auth 校验 Server 会话(已登录)
  → 直接生成 code，跳回 flow/sso/callback
  → flow 用 code 换 token
  → flow 保存本地会话
  → 重定向回 /apply
```

> **关键点**：用户**不需要再输密码**，因为 Server 端会话还在。

### 3.4 全端注销

```
用户点击"退出登录"
  → admin POST /sso/logout (携带 token)
  → auth Server 端注销会话
  → auth 推送注销消息到所有 Client（HTTP 回调）
  → 各 Client 清本地会话
  → 返回注销成功
  → 浏览器跳转登录页
```

### 3.5 踢人下线

#### 场景一：同账号第二台设备登录

通过 Sa-Token 配置实现：

```yaml
sa-token:
  is-concurrent: false        # 不允许同账号并发登录
  is-kickout: true            # 启用踢人下线
```

效果：用户在 PC 上登录 → 用户在手机上登录 → PC 端下次请求收到 401（code=40102 被踢下线）→ 前端跳转登录。

#### 场景二：管理员主动踢下线

```
管理员在"在线用户"页面点"强制下线"
  → POST /sso/kickout?loginId=10001&deviceType=PC
  → StpUtil.kickout(10001, "PC")
  → 发 MQ 事件 user.kickout
  → message-service 消费 → WebSocket 推送到该用户
  → 浏览器弹窗"您的登录已失效，请重新登录" → 跳 SSO
```

### 3.6 Token 续期

```
前端请求收到 401（code=40101 Token 过期）
  → 前端调 POST /sso/refresh，body 带 refresh_token
  → auth 校验 refresh_token 有效性（一次性使用）
  → 颁发新 access_token（2h）+ 新 refresh_token（7d）
  → 前端替换 Token，重试原请求
```

> **Refresh Token 必须是一次性使用**，用后立即失效，防止重放攻击。

### 3.7 前端 401 拦截器逻辑

```typescript
// vue-web-ui/packages/api/src/request.ts
service.interceptors.response.use(
  res => res,
  async err => {
    if (err.response?.status === 401) {
      const code = err.response.data?.code;
      if (code === 40101) {
        // Token 过期，尝试 Refresh
        const refreshed = await tryRefreshToken();
        if (refreshed) return retry(err.config);
      }
      if (code === 40102) {
        // 被踢下线
        window.$message?.error('您的登录已失效，请重新登录');
        await redirectToSSO();
      }
    }
    return Promise.reject(err);
  }
);

function redirectToSSO() {
  const redirect = encodeURIComponent(window.location.href);
  window.location.href = `${import.meta.env.VITE_SSO_SERVER_URL}/sso/auth?redirect=${redirect}`;
}
```

## 4. WebSocket 协议规范

### 4.1 端点清单

| 端点 | 服务 | 用途 |
|------|------|------|
| `/ws/monitor/{userId}` | spring-cloud-monitor | 实时指标推送 |
| `/ws/message/{userId}` | spring-cloud-message | 站内信、任务提醒、客服消息 |

### 4.2 握手鉴权

WebSocket 握手时通过 query 参数携带 Token：

```
ws://localhost:8080/ws/monitor/10001?token=xxx
```

服务端在 `AuthHandshakeHandler` 中校验 Token，校验通过后绑定到 `Channel.attr(...)`。

### 4.3 消息格式

```json
{
  "type": "METRIC",
  "to": "10001",
  "content": { ... },
  "timestamp": 1722470400000
}
```

| type | 含义 |
|------|------|
| METRIC | 监控指标（monitor 服务） |
| NOTICE | 站内信通知（message 服务） |
| TASK_TODO | 任务待办提醒 |
| ALERT | 告警通知 |
| CUSTOMER_SERVICE | 客服消息 |
| KICKOUT | 被踢下线通知 |
| PING | 心跳 |
| PONG | 心跳响应 |

### 4.4 心跳机制

- 客户端每 30s 发 `{"type":"PING"}`
- 服务端响应 `{"type":"PONG"}`
- 服务端 60s 无响应则关闭连接
- 客户端断线后自动重连（指数退避：1s → 2s → 4s → 8s → 16s）

### 4.5 路由

服务端维护 `userId → List<Channel>` 路由表（`ConcurrentHashMap`），支持一个用户多端在线。

## 5. SSE 流式响应规范（AI 对话）

### 5.1 接口约定

```
POST /api/ai/chat/stream
Content-Type: application/json
Accept: text/event-stream

{
  "conversationId": "uuid",
  "message": "请解释 RAG 是什么"
}
```

### 5.2 响应格式

```
data: {"type":"CHUNK","content":"RAG 是"}\n\n
data: {"type":"CHUNK","content":"检索增强"}\n\n
data: {"type":"CHUNK","content":"生成"}\n\n
data: {"type":"RETRIEVAL","docs":[{"title":"...","snippet":"..."}]}\n\n
data: {"type":"DONE","messageId":"xxx","tokens":150}\n\n
```

| type | 含义 |
|------|------|
| CHUNK | LLM 生成的一个 token 片段 |
| RETRIEVAL | RAG 检索到的相关文档 |
| DONE | 流式结束 |
| ERROR | 出错 |

### 5.3 前端处理

```typescript
const eventSource = new EventSource(`/api/ai/chat/stream?...`);
eventSource.onmessage = (e) => {
  const data = JSON.parse(e.data);
  if (data.type === 'CHUNK') {
    appendToUI(data.content);
  } else if (data.type === 'DONE') {
    closeStream();
  }
};
```

> 注意：浏览器原生 `EventSource` 只支持 GET，POST 需用 `fetch` + `ReadableStream` 或 `@microsoft/fetch-event-source` 库。

## 6. RabbitMQ 事件总线

### 6.1 Exchange / Queue 设计

| Exchange | 类型 | Queue | 路由键 | 生产者 | 消费者 |
|----------|------|-------|--------|--------|--------|
| `user.login` | fanout | `user.login.log` | - | auth | log |
| `user.login` | fanout | `user.login.message` | - | auth | message |
| `user.kickout` | fanout | `user.kickout.message` | - | auth | message |
| `user.update` | topic | `user.update.*` | `user.update.system` | system | message、log、search |
| `task.todo` | direct | `task.todo.message` | `task.todo` | workflow | message |
| `alert.trigger` | direct | `alert.trigger.message` | `alert.trigger` | monitor | message |
| `doc.uploaded` | direct | `doc.uploaded.search` | `doc.uploaded` | ai | search |
| `log.operation` | topic | `log.operation.persist` | `log.operation.#` | 所有 | log |

### 6.2 事件基类

所有事件**必须**继承 `BaseEvent`：

```java
@Data
@SuperBuilder
public abstract class BaseEvent {
    private String eventId;        // UUID，用于幂等
    private String eventType;     // 事件类型
    private String source;        // 来源服务名
    private LocalDateTime timestamp;
    private Long userId;          // 触发用户（可选）
}

public class UserLoginEvent extends BaseEvent {
    private Long loginId;
    private String deviceType;
    private String ip;
    private LocalDateTime loginTime;
}
```

### 6.3 幂等消费

`AbstractEventListener<T>` 用 Redis 自动去重：

```java
public abstract class AbstractEventListener<T extends BaseEvent> {
    public void onMessage(T event) {
        String key = "mq:idempotent:" + event.getEventId();
        if (!redisTemplate.setIfAbsent(key, "1", Duration.ofHours(24))) {
            return;  // 已消费，跳过
        }
        try {
            handle(event);
        } catch (Exception e) {
            redisTemplate.delete(key);  // 失败回滚
            throw e;
        }
    }
    protected abstract void handle(T event);
}
```

### 6.4 失败重试与死信

- 消费失败自动重试 3 次（Spring AMQP 默认）
- 超过 3 次进死信队列 `dead.queue`
- 死信队列由 `spring-cloud-test` 的定时任务告警

## 7. Dubbo RPC 协议

### 7.1 接口定义

Dubbo 接口**必须**定义在 `spring-cloud-common-core` 的 `rpc` 包，由被调方实现：

```java
// spring-cloud-common-core/src/main/java/com/xytang/common/core/rpc/UserRpcService.java
public interface UserRpcService {
    UserDTO getById(Long id);
    List<UserDTO> listByIds(List<Long> ids);
    List<UserDTO> listByDept(Long deptId);
}
```

### 7.2 Provider 实现

被调方（spring-cloud-system）实现接口：

```java
@DubboService
@RequiredArgsConstructor
public class UserRpcProvider implements UserRpcService {
    private final UserService userService;

    @Override
    public UserDTO getById(Long id) {
        return userService.getDtoById(id);
    }
    // ...
}
```

### 7.3 Consumer 调用

调用方（如 spring-cloud-workflow）通过 `@DubboReference` 注入：

```java
@Service
@RequiredArgsConstructor
public class WorkflowServiceImpl {
    @DubboReference
    private UserRpcService userRpcService;

    public void approve(Long taskId, Long approverId) {
        UserDTO approver = userRpcService.getById(approverId);
        // ...
    }
}
```

### 7.4 调用清单

| 场景 | 调用方 | 被调方 | 方法 |
|------|--------|--------|------|
| 用户信息查询 | workflow | system | `UserRpcService.getById` |
| 部门树查询 | workflow | system | `DeptRpcService.tree` |
| 文件元数据 | portal | file | `FileRpcService.getMeta` |
| 用户角色 | monitor | system | `UserRpcService.getRoles` |
| 字典数据 | 所有 | system | `DictRpcService.getDataByType` |

## 8. CORS 跨域规范

### 8.1 网关全局 CORS

```yaml
# Nacos: spring-cloud-gateway.yaml
spring:
  cloud:
    gateway:
      globalcors:
        cors-configurations:
          '[/**]':
            allowed-origin-patterns:
              - 'https://*.example.com'
              - 'http://localhost:5173'
            allowed-methods: '*'
            allowed-headers: '*'
            exposed-headers: ['X-Trace-Id', 'Authorization']
            allow-credentials: true
            max-age: 3600
```

### 8.2 规范

- **禁止** `Access-Control-Allow-Origin: *`（必须显式白名单）
- `Allow-Credentials: true` 时**必须**用 `Origin-Patterns` 而非 `Origins`
- 预检请求缓存 1 小时

## 9. 错误处理统一约定

### 9.1 后端异常类层次

```
RuntimeException
  └── BusinessException (com.xytang.common.core.exception)
        ├── AuthException          (401, 认证异常)
        ├── PermissionException    (403, 权限异常)
        ├── ResourceNotFoundException (404)
        ├── ConflictException      (409)
        ├── RateLimitException     (429)
        ├── BusinessException     (500, 业务异常)
        └── SystemException       (500, 系统异常)
```

### 9.2 全局异常处理

`spring-cloud-common-web` 的 `GlobalExceptionHandler` 统一捕获：

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public R<Void> handleBusiness(BusinessException e) {
        log.warn("[业务异常] code={} msg={}", e.getCode(), e.getMessage());
        return R.fail(e.getCode(), e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public R<Void> handleValidation(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
            .map(fe -> fe.getField() + ": " + fe.getDefaultMessage())
            .collect(Collectors.joining("; "));
        return R.fail(400, msg);
    }

    @ExceptionHandler(Exception.class)
    public R<Void> handleSystem(Exception e) {
        log.error("[系统异常]", e);
        return R.fail(500, "服务器内部错误");
    }
}
```

### 9.3 前端错误展示

| code | 处理 |
|------|------|
| 400 | `$message.warning(msg)` |
| 401 (40101) | 尝试 refresh，失败跳登录 |
| 401 (40102) | 弹窗"登录已失效"，跳登录 |
| 403 | `$message.error("无权限")` |
| 404 | `$message.warning("资源不存在")` |
| 409 | `$message.warning(msg)` |
| 429 | `$message.warning("操作过于频繁")` |
| 500 | `$message.error("服务器异常，traceId=xxx")` |

## 10. 安全加固清单

| 项 | 措施 |
|----|------|
| 密码存储 | BCrypt 加盐（cost=10） |
| 密码传输 | 全站 HTTPS + 前端 RSA 加密密码字段 |
| 登录失败 | 5 次锁定 15 分钟（Redisson 计数） |
| 验证码 | 滑动验证码（tianai-captcha） |
| Token 长度 | Sa-Token 默认 64 字符随机串 |
| 防重放 | 请求头 timestamp + nonce + sign |
| XSS | Vue 默认转义 + DOMPurify 处理富文本 |
| CSRF | Sa-Token Token 模式天然防 CSRF |
| SQL 注入 | MyBatis-Plus 参数化查询 |
| 越权 | 数据权限拦截器 + 接口级 @SaCheckPermission |
| 接口限流 | Sentinel 按路由/IP/用户限流 |
| 敏感字段加密 | ShardingSphere AES 加密手机号/身份证 |
