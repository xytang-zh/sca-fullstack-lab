# 10 · 消息中心服务需求（spring-cloud-message）

> 端口 8086，统一的消息出口：MQ 消费 → WebSocket 推送 → 站内信 / 邮件 / 短信。

---

## 1. 模块定位

| 维度 | 值 |
|------|-----|
| 服务名 | `spring-cloud-message` |
| HTTP 端口 | 8086 |
| Dubbo 端口 | 20886 |
| WebSocket 端口 | 9091 |
| XXL-JOB 执行器端口 | 10004 |
| 顶级包 | `com.xytang.message` |
| 启动类 | `SpringCloudMessageApplication` |
| 角色 | 消息出口 + 站内信 + 在线客服 |
| 依赖 | MySQL、Redis、RabbitMQ、Nacos |

## 2. 功能清单

### 2.1 MQ 消费模块

| 功能 | 描述 | 业务规则 |
|------|------|----------|
| 消费 user.login | 登录成功事件 | 写登录日志 + 推欢迎消息 |
| 消费 user.kickout | 踢下线事件 | WebSocket 推送"被踢下线" |
| 消费 user.update | 用户变更事件 | 刷新缓存 |
| 消费 task.todo | 任务待办事件 | 推送 WebSocket + 站内信 |
| 消费 alert.trigger | 告警事件 | 推送 WebSocket + 邮件/短信 |
| 消费 article.published | 文章发布事件 | 同步 ES |
| 幂等消费 | eventId 去重 | Redis SETNX |

### 2.2 WebSocket 推送模块

| 功能 | 描述 | 实现要点 |
|------|------|----------|
| Netty Server | 端口 9091 | ChannelRouter 路由 |
| 用户路由 | userId → List<Channel> | 一个用户多端在线 |
| 握手鉴权 | Token 校验 | query 参数 |
| 心跳机制 | 30s PING / 60s 超时 | 自动关闭 |
| 离线消息 | 用户不在线时存 Redis | 上线后推送 |
| 消息确认 | 客户端 ACK | 防丢消息 |

### 2.3 站内信模块

| 功能 | 描述 | 业务规则 |
|------|------|----------|
| 站内信 CRUD | 管理员发送 | 全员/指定人 |
| 已读未读 | 标记 + 查询 | |
| 全部已读 | 批量 | |
| 批量删除 | | |
| 未读数 | 按当前用户 | |
| 类型 | 系统、任务、告警、客服 | |

### 2.4 邮件模块

| 功能 | 描述 | 业务规则 |
|------|------|----------|
| 发送邮件 | 简单文本/HTML | Thymeleaf 模板 |
| 模板管理 | CRUD | 含变量 |
| 邮件队列 | 异步发送 | 防止超时 |
| 发送记录 | 查询 | 含失败原因 |

### 2.5 短信模块

| 功能 | 描述 | 业务规则 |
|------|------|----------|
| 发送短信 | 阿里云/腾讯云 | 限流 1/min |
| 模板管理 | CRUD | |
| 发送记录 | 查询 | 含回执 |

### 2.6 在线客服模块

| 功能 | 描述 | 业务规则 |
|------|------|----------|

## 3. 数据模型

### 3.1 MySQL 表

```sql
-- 站内信
CREATE TABLE sys_message (
    id BIGINT PRIMARY KEY,
    user_id BIGINT COMMENT '接收人',
    title VARCHAR(100),
    content TEXT,
    message_type TINYINT COMMENT '1=系统 2=任务 3=告警 4=客服',
    biz_id BIGINT COMMENT '业务 ID',
    is_read TINYINT DEFAULT 0,
    read_time DATETIME,
    create_by BIGINT,
    create_time DATETIME,
    INDEX idx_user_read (user_id, is_read),
    INDEX idx_create_time (create_time)
);

-- 邮件模板
CREATE TABLE sys_email_template (
    id BIGINT PRIMARY KEY,
    template_name VARCHAR(50),
    template_code VARCHAR(50) UNIQUE,
    subject VARCHAR(200),
    content TEXT COMMENT 'Thymeleaf 模板',
    variables VARCHAR(500) COMMENT 'JSON 变量列表',
    status TINYINT DEFAULT 1,
    create_time DATETIME, update_time DATETIME
);

-- 邮件发送记录
CREATE TABLE biz_email_log (
    id BIGINT PRIMARY KEY,
    to_email VARCHAR(100),
    subject VARCHAR(200),
    content TEXT,
    template_code VARCHAR(50),
    status TINYINT COMMENT '1=发送中 2=成功 3=失败',
    error_msg VARCHAR(500),
    create_time DATETIME,
    INDEX idx_to_email (to_email),
    INDEX idx_create_time (create_time)
);

-- 短信模板
CREATE TABLE sys_sms_template (
    id BIGINT PRIMARY KEY,
    template_name VARCHAR(50),
    template_code VARCHAR(50) UNIQUE,
    content VARCHAR(500),
    variables VARCHAR(500),
    provider VARCHAR(20) COMMENT 'aliyun/tencent',
    status TINYINT DEFAULT 1,
    create_time DATETIME, update_time DATETIME
);

-- 短信发送记录
CREATE TABLE biz_sms_log (
    id BIGINT PRIMARY KEY,
    to_phone VARCHAR(20),
    template_code VARCHAR(50),
    content VARCHAR(500),
    provider VARCHAR(20),
    status TINYINT,
    error_msg VARCHAR(500),
    send_time DATETIME,
    receive_time DATETIME,
    INDEX idx_phone (to_phone)
);

-- 客服会话
CREATE TABLE biz_customer_session (
    id BIGINT PRIMARY KEY,
    session_no VARCHAR(50) UNIQUE,
    visitor_id BIGINT COMMENT '访客 ID',
    agent_id BIGINT COMMENT '客服 ID',
    status TINYINT COMMENT '1=排队 2=进行中 3=已结束',
    start_time DATETIME,
    end_time DATETIME,
    INDEX idx_status (status)
);

-- 客服消息
CREATE TABLE biz_customer_message (
    id BIGINT PRIMARY KEY,
    session_id BIGINT,
    sender_type TINYINT COMMENT '1=访客 2=客服',
    content TEXT,
    create_time DATETIME,
    INDEX idx_session (session_id)
);
```

### 3.2 Redis Key

| Key | 类型 | TTL | 说明 |
|-----|------|-----|------|
| `message:online:{userId}` | String | 60s | 用户在线状态 |
| `message:queue:{userId}` | List | 7d | 离线消息队列 |
| `message:unread:{userId}` | String | - | 未读数 |
| `message:customer:queue` | List | - | 访客排队队列 |
| `message:customer:agent:{agentId}` | Set | - | 客服当前会话 |

## 5. WebSocket 协议

### 5.1 端点

```
ws://localhost:8080/ws/message/{userId}?token=xxx
```

### 5.2 消息格式

```json
// 站内信通知
{
  "type": "NOTICE",
  "to": "10001",
  "content": { "id": 1, "title": "新通知", "messageType": 1 }
}

// 任务待办
{
  "type": "TASK_TODO",
  "to": "10001",
  "content": { "taskId": 1, "title": "请假审批" }
}

// 告警
{
  "type": "ALERT",
  "to": "10001",
  "content": { "rule": "CPU 高", "service": "system", "value": 0.92 }
}

// 被踢下线
{
  "type": "KICKOUT",
  "to": "10001",
  "content": { "reason": "管理员下线" }
}

// 客服消息
{
  "type": "CUSTOMER_SERVICE",
  "to": "10001",
  "content": { "sessionId": 1, "sender": "agent", "text": "您好" }
}

// 心跳
{ "type": "PING" }
{ "type": "PONG" }

// 确认
{ "type": "ACK", "messageId": "xxx" }
```

### 5.3 离线消息

```
1. 用户 A 不在线
2. message-service 接到推送给 A 的消息
3. 检查 Redis message:online:A 不存在
4. 推入 Redis List message:queue:A
5. 用户 A 上线 → WebSocket 连接
6. 服务端推送离线消息（按时间正序）
7. 客户端 ACK 后从 Redis 删除
```

## 7. 关键业务流程

### 7.1 任务待办推送流程

```
1. workflow-service 审批通过
2. 发 MQ task.todo（含 toUserId, taskTitle, ...）
3. message-service 消费：
   - 写 sys_message
   - 检查 Redis message:online:{toUserId}
4. 在线：WebSocket 推送 TASK_TODO
5. 不在线：推入 Redis message:queue:{toUserId}
6. 前端铃铛数 +1
```

### 7.2 告警推送流程

```
1. monitor-service 检测到 CPU > 80%
2. 发 MQ alert.trigger（含 toUserId, rule, value, ...）
3. message-service 消费：
   - 写 sys_message（type=3 告警）
   - WebSocket 推送 ALERT
   - 同时调 email-service 发邮件（CRITICAL 级别）
   - 同时调 sms-service 发短信（CRITICAL 级别）
4. 前端弹窗 + 铃铛
```

### 7.3 客服分配流程

```
1. 访客点击"在线客服"
2. POST /messages/customer-service/connect
3. message-service：
   - 加入 Redis 排队队列 message:customer:queue
   - 尝试分配客服：
     - 获取所有在线客服
     - 用 Redisson 分布式锁选择会话最少的客服
     - 创建 biz_customer_session
     - 推送 CUSTOMER_SERVICE 给访客和客服
4. 没有空闲客服：返回"前面还有 N 人"
```

## 10. 实现要点

| 项 | 要点 |
|----|------|
| Netty 共享 | 与 monitor-service 共用 spring-cloud-common-netty |
| ChannelRouter | 线程安全（ConcurrentHashMap） |
| 离线消息 | Redis List 存储，上限 100 条 |
| ACK 机制 | 客户端收到消息必须回 ACK，否则重发 |
| 幂等消费 | eventId 去重，Redis SETNX 24h |
| 客服分配 | Redisson 分布式锁防并发分配 |
| 邮件队列 | 异步发送，避免业务阻塞 |
| 短信限流 | Redisson RRateLimiter，1 用户 1 分钟 1 条 |
