# 12 · 文件服务需求（spring-cloud-file）

> 端口 8088，基于 MinIO 的对象存储服务，支持大文件分片上传、断点续传、预签名 URL。

---

## 1. 模块定位

| 维度 | 值 |
|------|-----|
| 服务名 | `spring-cloud-file` |
| HTTP 端口 | 8088 |
| Dubbo 端口 | 20888 |
| 顶级包 | `com.xytang.file` |
| 启动类 | `SpringCloudFileApplication` |
| 角色 | 文件存储中心 |
| 依赖 | MinIO、MySQL、Redis、Nacos |

## 2. 功能清单

### 2.1 上传模块

| 功能 | 描述 | 业务规则 |
|------|------|----------|
| 单文件上传 | 表单上传 | 最大 100 MB |
| 批量上传 | 多文件并发 | 单批最多 10 个 |
| 分片上传 | init/upload/complete 三步 | 每片 5 MB |
| 断点续传 | 失败重试只传失败分片 | uploadId 状态 |
| 秒传 | MD5 校验已存在 | 直接复用 |
| 预签名直传 | 前端直传 MinIO | 后端只签名 |

### 2.2 下载模块

| 功能 | 描述 | 业务规则 |
|------|------|----------|
| 普通下载 | 流式下载 | 大文件不撑爆内存 |
| 断点续传 | Range 请求 | HTTP 206 |
| 临时链接 | 预签名下载 URL | 5 分钟有效 |

## 3. 数据模型

### 3.1 MySQL 表

```sql
CREATE TABLE biz_file (
    id BIGINT PRIMARY KEY,
    file_name VARCHAR(255) NOT NULL,
    original_name VARCHAR(255),
    file_path VARCHAR(500) COMMENT 'MinIO 完整路径',
    bucket VARCHAR(50),
    md5 VARCHAR(32) UNIQUE COMMENT '秒传校验',
    size BIGINT,
    file_type VARCHAR(20) COMMENT 'pdf/jpg/mp4/...',
    mime_type VARCHAR(100),
    owner_id BIGINT COMMENT '所属用户',
    service_name VARCHAR(50) COMMENT '所属服务',
    parent_id BIGINT DEFAULT 0 COMMENT '目录 ID',
    is_directory TINYINT DEFAULT 0,
    status TINYINT DEFAULT 1 COMMENT '1=正常 0=回收站',
    upload_id VARCHAR(100) COMMENT '分片上传 ID',
    chunk_count INT DEFAULT 0,
    chunk_uploaded INT DEFAULT 0,
    expire_time DATETIME COMMENT '临时文件过期',
    create_time DATETIME,
    update_time DATETIME,
    del_flag TINYINT DEFAULT 0,
    INDEX idx_md5 (md5),
    INDEX idx_owner (owner_id),
    INDEX idx_parent (parent_id)
);

CREATE TABLE biz_file_chunk (
    id BIGINT PRIMARY KEY,
    file_id BIGINT,
    chunk_index INT,
    chunk_md5 VARCHAR(32),
    size BIGINT,
    uploaded TINYINT DEFAULT 0,
    upload_time DATETIME,
    INDEX idx_file (file_id)
);

CREATE TABLE biz_file_quota (
    id BIGINT PRIMARY KEY,
    owner_id BIGINT,
    owner_type TINYINT COMMENT '1=用户 2=服务',
    total_size BIGINT DEFAULT 10737418240 COMMENT '10 GB',
    used_size BIGINT DEFAULT 0,
    file_count INT DEFAULT 0,
    INDEX idx_owner (owner_id, owner_type)
);
```

### 3.2 Redis Key

| Key | 类型 | TTL | 说明 |
|-----|------|-----|------|
| `file:upload:status:{uploadId}` | Hash | 24h | 分片上传状态 |
| `file:presign:{uuid}` | String | 5min | 预签名 URL 缓存 |
| `file:quota:lock:{userId}` | String | 10s | 配额更新锁 |

## 6. 关键业务流程

### 6.1 分片上传流程

```
1. 前端选择大文件（如 1GB）
2. POST /files/upload/init
   - body: { fileName, size, md5, chunkSize }
   - 后端：
     - 检查 md5（秒传）
     - 调 MinIO init multipart upload → uploadId
     - 写 biz_file（status=uploading）
     - 写 biz_file_chunk N 条
   - 返回 { fileId, uploadId, chunkCount, chunkSize }
3. 前端切片上传（并发 5 个）
   POST /files/upload/chunks
   - body: { uploadId, chunkIndex, chunkData }
   - 后端：
     - 调 MinIO uploadPart
     - 更新 biz_file_chunk.uploaded=1
     - 更新 biz_file.chunk_uploaded++
4. 全部分片完成
   POST /files/upload/complete
   - body: { uploadId }
   - 后端：
     - 调 MinIO completeMultipartUpload 合并
     - 更新 biz_file.status=1
     - 更新配额
5. 失败重试：只传 uploaded=0 的分片
```

### 6.2 秒传流程

```
1. 前端计算文件 MD5
2. POST /files/check-md5
   - body: { md5 }
3. 后端：
   - 查 biz_file where md5=?
   - 找到：返回 { exist: true, fileId: xxx }
   - 找不到：返回 { exist: false }
4. 找到：前端直接复用，不实际上传
```

### 6.3 预签名直传流程

```
1. 前端 GET /files/presign?fileName=xxx&size=1024
2. 后端：
   - 调 MinIO presignedPutObject 生成 URL（5min）
   - 返回 { url, expireAt }
3. 前端直接 PUT 文件到该 URL（不经后端）
4. 上传完成后调 POST /files/confirm 通知后端
5. 后端写 biz_file 记录
```

## 7. 配置文件

```yaml
server:
  port: 8088

spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/aurora_file
  servlet:
    multipart:
      max-file-size: 100MB
      max-request-size: 600MB

# MinIO
minio:
  endpoint: http://127.0.0.1:9000
  external-endpoint: https://files.example.com   # 前端直传用
  access-key: aurora
  secret-key: aurora
  buckets:
    files: aurora-files
    public: aurora-public
    temp: aurora-temp
    ai-documents: ai-documents

# 分片上传
file:
  upload:
    chunk-size: 5242880    # 5 MB
    max-concurrent: 5
    expire-hours: 24
  preview:
    kkfileview-url: https://preview.example.com
  quota:
    user-default: 10737418240    # 10 GB
    service-default: 107374182400   # 100 GB
```

## 9. 实现要点

| 项 | 要点 |
|----|------|
| MinIO 客户端 | 用官方 Java SDK，不要自己实现 |
| 分片大小 | 5 MB（MinIO 最小分片） |
| 并发上传 | 前端并发 5 个分片 |
| 秒传 | MD5 唯一索引 |
| 预签名 | 用 `presignedPutObject` / `presignedGetObject` |
| 缩略图 | 用 MinIO + ImageMagick 或 Thumbnailator |
| Office 预览 | 集成 KKFileView 独立容器 |
| 大文件下载 | 用 Range 请求支持断点续传 |
| 配额校验 | 上传前校验，超限拒绝 |
| 临时文件 | 24h 自动清理 |
