# 05 · 认证中心需求（spring-cloud-auth）

> 端口 8081，统一身份认证中心（SSO Server + OAuth2 Server），承担登录、SSO、踢人下线、OAuth2、会话治理、风控。

---

## 1. 模块定位

| 维度 | 值 |
|------|-----|
| 服务名 | `spring-cloud-auth` |
| HTTP 端口 | 8081 |
| Dubbo 端口 | 20881 |
| 顶级包 | `com.xytang.auth` |
| 启动类 | `SpringCloudAuthApplication` |
| 角色 | SSO Server + OAuth2 Server |
| 依赖 | Redis、MongoDB（登录日志）、RabbitMQ（事件 `user.login` / `user.kickout`） |

## 2. 功能清单

### 2.1 登录模块

| 功能 | 描述 | 业务规则 |
|------|------|----------|
| 账号密码登录 | 用户名 + 密码 + 滑动验证码 | 失败 5 次锁定 15 分钟 |
| 短信登录 | 手机号 + 短信验证码 | 验证码 5 分钟有效，每天 10 条上限 |
| 邮箱登录 | 邮箱 + 邮件验证码 | 同上 |
| 扫码登录 | 二维码 + 移动端确认 | 二维码 5 分钟有效 |
| 获取验证码 | 滑动验证码图片 | tianai-captcha |
| 发送短信 | 调用 message-service | 1 分钟限 1 条，1 小时限 5 条 |
| 发送邮件 | 调用 message-service | 同上 |

### 2.2 SSO Server 模块

| 功能 | 描述 | 实现要点 |
|------|------|----------|
| SSO 登录入口 | `GET /sso/auth?redirect=xxx` | 校验 Server 会话 |
| SSO 登录提交 | `POST /sso/auth` | 账号密码 + 验证码 |
| 颁发授权码 | `GET /sso/code` | 60s 有效，一次性 |
| Code 换 Token | `POST /sso/code2session` | Client 凭证 + code |
| 全端注销 | `POST /sso/logout` | 一处注销，全端下线 |
| 单端注销 | `POST /sso/logoutByAlone` | 仅当前 Client 下线 |

### 2.3 OAuth2 模块

| 功能 | 描述 | 实现要点 |
|------|------|----------|
| 授权页 | `GET /oauth2/authorize` | 用户登录 + 同意授权 |
| 颁发 Token | `POST /oauth2/token` | code 换 access_token + refresh_token |
| 用户信息 | `GET /oauth2/userinfo` | 第三方获取用户信息 |
| Refresh Token | `POST /oauth2/refresh` | 一次性使用 |
| 撤销 Token | `POST /oauth2/revoke` | 主动撤销 |
| Client 管理 | CRUD | 管理员操作 |

### 2.4 会话治理模块

| 功能 | 描述 | 业务规则 |
|------|------|----------|
| 在线用户列表 | 分页查询 | 支持用户名/IP/设备筛选 |
| 在线用户详情 | 单用户会话详情 | 所有设备会话 |
| 强制下线 | 按 loginId + deviceType | 踢下线 + 发 MQ 通知 |
| 按 Token 下线 | 按 token 踢 | 单点下线 |
| 封禁用户 | 全端注销 + 标记 | 不可再登录 |

### 2.5 风控模块

| 功能 | 描述 | 业务规则 |
|------|------|----------|
| 登录失败计数 | Redis Key `auth:login:fail:{username}` | TTL 15min，5 次锁定 |
| IP 黑名单 | Redis Key `auth:ip:blacklist:{ip}` | TTL 24h，1 小时失败 50 次拉黑 |
| 异地登录告警 | 上次 IP 与本次跨省 | 发 MQ `alert.trigger` |
| 滑动验证码 | tianai-captcha | 3 次失败后强制验证 |

### 2.6 第三方登录（可选）

| 功能 | 描述 |
|------|------|
| 微信扫码 | 微信开放平台 OAuth2 |
| GitHub | GitHub OAuth App |
| Google | Google OAuth2 |

## 3. 数据模型

### 3.1 MySQL 表

```sql
-- sys_user 表（auth 只读，CRUD 在 system）
CREATE TABLE sys_user (
    id BIGINT PRIMARY KEY COMMENT '雪花 ID',
    username VARCHAR(50) NOT NULL UNIQUE,
    password VARCHAR(100) NOT NULL COMMENT 'BCrypt 加盐',
    phone VARCHAR(20),
    email VARCHAR(100),
    status TINYINT DEFAULT 1 COMMENT '1=正常 0=禁用',
    last_login_ip VARCHAR(50),
    last_login_time DATETIME,
    create_time DATETIME,
    update_time DATETIME,
    del_flag TINYINT DEFAULT 0
);

-- OAuth2 Client 表
CREATE TABLE oauth2_client (
    id BIGINT PRIMARY KEY,
    client_id VARCHAR(50) NOT NULL UNIQUE,
    client_secret VARCHAR(100) NOT NULL COMMENT 'BCrypt 加盐',
    client_name VARCHAR(100),
    redirect_uris TEXT COMMENT 'JSON 数组',
    grant_types VARCHAR(100) COMMENT 'authorization_code,refresh_token',
    scope VARCHAR(100) COMMENT 'userinfo,profile',
    access_token_validity INT DEFAULT 7200,
    refresh_token_validity INT DEFAULT 604800,
    status TINYINT DEFAULT 1,
    create_time DATETIME,
    update_time DATETIME
);

-- 封禁用户表
CREATE TABLE auth_banned_user (
    id BIGINT PRIMARY KEY,
    user_id BIGINT NOT NULL,
    reason VARCHAR(200),
    banned_by BIGINT,
    banned_time DATETIME,
    expire_time DATETIME COMMENT 'NULL=永久'
);
```

### 3.2 Redis Key

| Key | 类型 | TTL | 说明 |
|-----|------|-----|------|
| `satoken:login:token:{token}` | String | 2h | Token → loginId |
| `satoken:login:session:{loginId}` | Hash | 2h | 用户会话 |
| `satoken:login:last-active:{loginId}` | String | 2h | 最后活跃时间 |
| `auth:login:fail:{username}` | String | 15min | 登录失败计数 |
| `auth:login:lock:{username}` | String | 15min | 锁定标记 |
| `auth:captcha:{key}` | String | 5min | 滑动验证码 |
| `auth:sms:code:{phone}` | String | 5min | 短信验证码 |
| `auth:email:code:{email}` | String | 5min | 邮箱验证码 |
| `auth:ip:blacklist:{ip}` | String | 24h | IP 黑名单 |
| `auth:ip:fail:{ip}` | String | 1h | IP 失败计数 |
| `auth:oauth2:code:{code}` | String | 60s | OAuth2 授权码 |
| `auth:oauth2:refresh:{token}` | String | 7d | Refresh Token |

## 5. 关键业务流程

### 5.1 SSO 首次登录（详细时序）

```
1. 用户访问 admin.example.com → Client A 校验本地会话（未登录）
2. Client A 302 跳转 auth.example.com/sso/auth?redirect=admin
3. Server GET /sso/auth → 校验 Server 会话（未登录）→ 返回登录页
4. 用户 POST /sso/auth（账号 + 密码 + 验证码）
5. Server 校验：
   - 验证码（captcha key 校验）
   - 登录失败次数（Redis auth:login:fail:xxx）
   - 账号密码（BCrypt 校验）
   - 用户状态（status=1）
6. Server StpUtil.login(loginId, deviceId)
   - 写 Redis satoken:login:session:{loginId}
7. Server 生成 code（Redis auth:sso:code:{code}，60s）
8. Server 302 跳回 admin.example.com/sso/callback?code=xxx
9. Client A POST /sso/code2session（code + client_name + sign）
10. Server 校验 code → 返回 loginId + token
11. Client A 保存本地会话 → 重定向回原页面
```

### 5.2 踢人下线

#### 场景一：同账号并发踢下线

通过 Sa-Token 配置自动实现：

```yaml
sa-token:
  is-concurrent: false
  is-kickout: true
```

效果：
- 用户在 PC 登录 → 在手机登录 → PC 端下次请求收到 401（code=40102）
- 前端拦截 40102 → 弹窗"登录已失效" → 跳 SSO

#### 场景二：管理员主动踢下线

```java
@PostMapping("/sso/kickout")
public R<Void> kickout(@RequestParam Long loginId,
                       @RequestParam(defaultValue = "PC") String deviceType) {
    StpUtil.kickout(loginId, deviceType);
    // 发 MQ 事件
    eventPublisher.publish(MqConstants.USER_KICKOUT,
        new UserKickoutEvent(loginId, deviceType, LoginUserContext.get()));
    return R.ok();
}
```

message-service 消费 `user.kickout` 事件 → 通过 WebSocket 推送到该用户浏览器。

### 5.3 Token 续期

```
1. 前端请求收到 401（code=40101）
2. 前端 POST /sso/refresh，body 带 refresh_token
3. Server 校验 refresh_token：
   - Redis auth:oauth2:refresh:{token} 是否存在
   - 是否已使用（用后立即删除，一次性）
4. Server 颁发新 access_token（2h）+ 新 refresh_token（7d）
5. 前端替换 Token，重试原请求
```

### 5.4 异地登录告警

```java
// 登录成功后
String currentIp = IpUtils.getRealAddressByIp(request);
String lastIp = user.getLastLoginIp();
if (lastIp != null && !IpUtils.isSameRegion(currentIp, lastIp)) {
    // 跨省 → 发告警事件
    eventPublisher.publish(MqConstants.ALERT_TRIGGER, new AlertEvent(
        "异地登录", loginId, lastIp, currentIp, LocalDateTime.now()
    ));
}
```

message-service 消费 → 推送 WebSocket 通知 + 邮件提醒。

## 6. Sa-Token 配置

```yaml
sa-token:
  token-name: Authorization
  token-prefix: Bearer
  timeout: 7200              # Access Token 2h
  active-timeout: -1
  is-concurrent: false        # 不允许同账号并发登录
  is-share: false
  is-kickout: true            # 启用踢人下线
  token-style: random-128
  is-log: false
  jwt-secret-key: ${SA_TOKEN_JWT_SECRET:change-me-in-prod}
  is-read-cookie: false
  is-read-header: true
  sso:
    mode: 2
    title: Aurora 认证中心
    auth-server-url: http://localhost:8081/sso
    is-slo: true
    slo-url: http://localhost:8081/sso/logout
    client-timeout: 60
  oauth2:
    is-code: true
    is-implicit: false
    is-client-credentials: true
    is-password: false
    refresh-token-timeout: 604800
    access-token-timeout: 7200
  alone-redis:
    host: ${REDIS_HOST:127.0.0.1}
    port: ${REDIS_PORT:6379}
    password: ${REDIS_PASSWORD:}
    database: 1
```

## 9. 实现要点与踩坑

| 项 | 要点 |
|----|------|
| 密码存储 | BCrypt cost=10，**禁止** MD5/SHA1 |
| 登录失败信息 | 统一返回"用户名或密码错误"，不区分用户名不存在 |
| Refresh Token | 一次性使用，用后立即删除 |
| 验证码 | 登录成功后立即失效 |
| Token 不打日志 | 禁止在日志中打印 Token、密码 |
| OAuth2 隐式模式 | 已废弃（OAuth2.1），不实现 |
| OAuth2 密码模式 | 已废弃，不实现 |
| SLO 回调 | Client 端必须实现 `/sso/logout` 回调接口接收注销通知 |
| 跨域 | SSO Server 必须配置 CORS 白名单所有 Client 域名 |
