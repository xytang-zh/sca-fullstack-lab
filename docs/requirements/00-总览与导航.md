# 00 · 项目需求总览与文档导航

> 本文档是 `sca-fullstack-lab` 项目需求文档的 **总入口**，提供整体架构、模块清单、文档导航与阅读顺序建议。
> 后续每一份文档对应一个微服务或一个公共能力，按"模块 → 功能 → 接口 → 数据模型 → 前端页面 → 实现要点"的结构展开。

---

## 1. 项目愿景

构建一个 **企业级一体化智能管理平台** 作为统一入口：

1. **管理员** 登录一次（SSO），可免登跳转到工作流、AI 助手、报表等多个子系统
2. 当登录态过期或被踢下线时，**自动跳回一体化登录中心**
3. 平台自身集成：系统管理、服务器监控、工作流审批、AI 知识库问答、消息推送、全文检索、文件管理、低代码报表、定时任务
4. **公开门户** 对外提供博客、新闻、产品介绍（SEO/GEO 友好）

---

## 2. 用户角色

| 角色 | 描述 | 主要场景 |
|------|------|----------|
| 超级管理员 | 全权限 | 配置菜单、角色、字典、监控大盘、报表设计 |
| 系统管理员 | 系统管理权限 | 用户、角色、参数管理 |
| 业务审批人 | 部门经理/HR/财务 | 处理审批任务 |
| 普通员工 | 申请发起人 | 发起请假/报销/合同申请 |
| 公开访客 | 未登录用户 | 浏览公开门户（博客、新闻、产品介绍） |

## 4. 后端 13 个微服务清单

| # | 服务 | 端口 | 类型 | 核心职责 |
|---|------|------|------|----------|
| 0 | `spring-cloud-gateway` | 8080 | 网关 | 路由转发、鉴权、限流、跨域、灰度 |
| 1 | `spring-cloud-auth` | 8081 | 认证 | 登录、SSO Server、踢人下线、OAuth2 |
| 2 | `spring-cloud-system` | 8082 | 业务 | 用户/角色/菜单/部门/字典/参数/通知 |
| 3 | `spring-cloud-monitor` | 8083 | 业务 | 服务器监控（TDengine + Netty 推送） |
| 4 | `spring-cloud-workflow` | 8084 | 业务 | Warm-Flow 4 类审批流程 |
| 5 | `spring-cloud-ai` | 8085 | 业务 | RAG 知识库问答、SSE 流式 |
| 6 | `spring-cloud-message` | 8086 | 基础设施 | RabbitMQ 消费、WebSocket 推送、站内信 |
| 7 | `spring-cloud-search` | 8087 | 基础设施 | ElasticSearch 全文检索 |
| 8 | `spring-cloud-file` | 8088 | 基础设施 | MinIO 上传/下载/预览 |
| 9 | `spring-cloud-log` | 8089 | 基础设施 | 操作日志、登录日志、审计 |
| 10 | `spring-cloud-portal` | 8090 | 业务 | 公开门户（博客/新闻/SEO） |
| 11 | `spring-cloud-job` | 8091 | 基础设施 | XXL-JOB 执行器 |
| 12 | `spring-cloud-report` | 8092 | 业务 | JimuReport 报表设计 |

## 9. 关键术语

| 术语 | 解释 |
|------|------|
| SSO | Single Sign-On，单点登录。一次登录，所有子系统免登 |
| SLO | Single Logout，单点注销。一处注销，所有子系统同步下线 |
| RAG | Retrieval-Augmented Generation，检索增强生成。先检索文档再让 LLM 生成 |
| RBAC | Role-Based Access Control，基于角色的访问控制 |
| ORM | Object-Relational Mapping，对象关系映射 |
| MQ | Message Queue，消息队列（本项目用 RabbitMQ） |
| WS | WebSocket，全双工通信协议 |
| SSE | Server-Sent Events，服务端推送（用于 AI 流式响应） |
| SSG | Static Site Generation，静态站点生成（portal 用） |
| SPA | Single Page Application，单页应用（admin 用） |
