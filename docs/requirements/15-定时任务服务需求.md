# 15 · 定时任务服务需求（spring-cloud-job）

> 端口 8091，XXL-JOB 执行器，所有定时任务集中管理。XXL-JOB Admin 独立部署（端口 8099）。

---

## 1. 模块定位

| 维度 | 值 |
|------|-----|
| 服务名 | `spring-cloud-job` |
| HTTP 端口 | 8091 |
| Dubbo 端口 | 20891 |
| XXL-JOB 执行器端口 | 10009 |
| 顶级包 | `com.xytang.job` |
| 启动类 | `SpringCloudJobApplication` |
| 角色 | XXL-JOB 执行器 + 集中任务调度 |
| 依赖 | MySQL（XXL-JOB 元数据）、Nacos |

> **部署模式**：
> - **XXL-JOB Admin**：独立 Docker 容器（端口 8099，见 docker-compose.infra.yml）
> - **spring-cloud-job**：业务服务，作为执行器注册到 Admin
> - 业务服务（如 system/monitor/ai）也可以自带执行器（推荐）

## 2. 功能清单

### 2.1 任务执行器

| 功能 | 描述 | 实现要点 |
|------|------|----------|
| 注册到 Admin | 启动时自动注册 | `XxlJobSpringExecutor` |
| 心跳保活 | 30s 一次 | 自动 |
| 任务接收 | 接收 Admin 调度 | `@XxlJob` 注解 |
| 任务日志 | 写执行日志 | `XxlJobHelper.log()` |
| 失败重试 | 3 次 | Admin 配置 |
| 任务分片 | 支持分片广播 | `ShardingUtil` |

### 2.2 典型任务清单

| 任务 | Cron | 说明 | 所在服务 |
|------|------|------|----------|
| `metricsAggregateJob` | `0 */1 * * * ?`（每分钟） | 监控指标聚合 → Redis | monitor |
| `aiMessageArchiveJob` | `0 0 1 * * ?`（每天 1 点） | MongoDB → ES 归档 | ai |
| `articleSyncToEsJob` | `0 0 2 * * ?`（每天 2 点） | MySQL → ES 全量同步 | search |
| `workflowRemindJob` | `0 */10 * * * ?`（每 10 分钟） | 流程超时催办 | workflow |
| `logCleanupJob` | `0 0 3 * * ?`（每天 3 点） | 清理 30 天前日志 | log |
| `createNextMonthTablesJob` | `0 0 4 25 * ?`（每月 25 号 4 点） | 建下月分表 | log |
| `archiveOldLogsJob` | `0 0 5 * * ?`（每天 5 点） | 6 个月前归档 | log |
| `sitemapJob` | `0 0 6 * * ?`（每天 6 点） | 生成 sitemap | portal |
| `tokenCleanupJob` | `0 0 7 * * ?`（每天 7 点） | 清理过期 Token | auth |

### 2.3 任务详情

#### 2.3.1 metricsAggregateJob（监控指标聚合）

```
描述：每分钟从 TDengine 取最新指标 → 写 Redis 缓存（供大盘快速查询）
实现：monitor-service
步骤：
1. 查 TDengine SELECT LAST(*) FROM aurora_metrics GROUP BY service_name
2. 写 Redis monitor:realtime:{service}（TTL 60s）
3. 大盘可直接查 Redis，避免每次打 TDengine
```

#### 2.3.2 aiMessageArchiveJob（AI 对话归档）

```
描述：每天凌晨把 MongoDB 对话 → ES 索引
实现：ai-service + search-service
步骤：
1. 查 MongoDB ai_messages（昨天 0 点到今天 0 点）
2. 转换为 ES 文档（含 sessionId, userId, role, content, ...）
3. 批量写入 ES ai_message 索引
4. 删除 MongoDB 中已归档的数据（可选）
```

#### 2.3.3 articleSyncToEsJob（文章全量同步）

```
描述：每天 2 点把 MySQL biz_article 全量同步到 ES article 索引
实现：search-service
步骤：
1. 创建新索引 article_new
2. 分页拉 MySQL（每页 1000）
3. 批量写入 ES _bulk API
4. alias 切换：article → article_new，删除 article_old
```

#### 2.3.4 workflowRemindJob（流程催办）

```
描述：每 10 分钟扫描超时流程实例，发催办通知
实现：workflow-service + message-service
步骤：
1. 查 flow_task where create_time < NOW - 24h AND status=1
2. 对每个超时任务：
   - 发 MQ task.remind
   - message-service 推送 WebSocket
3. 记录催办次数（同任务最多催 3 次）
```

#### 2.3.5 logCleanupJob（日志清理）

```
描述：每天 3 点清理 30 天前的 MongoDB 日志
实现：log-service
步骤：
1. 查 MongoDB log_operation where createTime < NOW - 30d
2. 批量删除（每批 1000）
3. 同样处理 log_login、log_audit
```

#### 2.3.6 createNextMonthTablesJob（建下月分表）

```
描述：每月 25 号 4 点建下月分表
实现：log-service
步骤：
1. 计算下月：LocalDate.now().plusMonths(1)
2. 格式化：yyyyMM
3. 对每张需要分表的表：
   - log_operation_archive_YYYYMM
   - log_login_archive_YYYYMM
4. 用 CREATE TABLE LIKE 创建
```

#### 2.3.7 archiveOldLogsJob（日志归档）

```
描述：每天 5 点把 6 个月前的日志从 MongoDB 移到 MySQL 归档表
实现：log-service
步骤：
1. 计算截止日期：NOW - 6 months
2. 分页查 MongoDB
3. 批量写入 MySQL log_operation_archive
4. 删除 MongoDB 中已归档的数据
```

#### 2.3.8 sitemapJob（生成 Sitemap）

```
描述：每天 6 点生成 sitemap.xml
实现：portal-service
步骤：
1. 查所有 status=1 的文章/新闻/产品
2. 生成 /portal/sitemap.xml
3. 提交到 Google Search Console
```

#### 2.3.9 tokenCleanupJob（Token 清理）

```
描述：每天 7 点清理过期的 Sa-Token
实现：auth-service
步骤：
1. 扫描 Redis satoken:login:token:* 检查 TTL
2. Sa-Token 自动清理（但需手动触发以防 Redis 残留）
3. 清理 auth:login:fail:* 过期计数
4. 清理 auth:captcha:* 过期验证码
```

## 3. 任务实现示例

```java
@Component
@RequiredArgsConstructor
@Slf4j
public class ArticleSyncToEsJob {

    private final ArticleRepository articleRepository;
    private final ElasticsearchClient esClient;

    @XxlJob("articleSyncToEsJob")
    public void execute() {
        try {
            XxlJobHelper.log("开始同步文章到 ES...");

            // 1. 创建新索引
            String newIndex = "article_" + System.currentTimeMillis();
            createIndex(newIndex);
            XxlJobHelper.log("创建新索引: " + newIndex);

            // 2. 分页拉 MySQL
            int pageNum = 1;
            int pageSize = 1000;
            long total = 0;
            while (true) {
                List<Article> articles = articleRepository.findPage(pageNum, pageSize);
                if (articles.isEmpty()) break;
                bulkIndex(newIndex, articles);
                total += articles.size();
                XxlJobHelper.log("已同步 " + total + " 篇");
                pageNum++;
            }

            // 3. alias 切换
            switchAlias("article", newIndex);
            XxlJobHelper.log("alias 切换完成");

            XxlJobHelper.handleSuccess("同步完成，共 " + total + " 篇");
        } catch (Exception e) {
            log.error("[articleSyncToEsJob] 失败", e);
            XxlJobHelper.handleFail("同步失败: " + e.getMessage());
        }
    }
}
```

## 4. XXL-JOB Admin 配置

### 4.1 容器（docker-compose.infra.yml）

```yaml
xxl-job-admin:
  image: xuxueli/xxl-job-admin:3.5.0
  container_name: aurora-xxl-job-admin
  restart: unless-stopped
  depends_on: [mysql]
  environment:
    PARAMS: >-
      --spring.datasource.url=jdbc:mysql://mysql:3306/xxl_job
      --spring.datasource.username=root
      --spring.datasource.password=${MYSQL_ROOT_PASSWORD}
      --xxl.job.accessToken=${XXL_JOB_ACCESS_TOKEN}
  ports: ["8099:8099"]
  volumes:
    - xxl_job_logs:/data/applogs
```

### 4.2 执行器配置

```yaml
xxl:
  job:
    admin:
      addresses: http://xxl-job-admin:8099
    executor:
      appname: aurora-${spring.application.name}
      address:
      ip:
      port: 10009
      logpath: /data/logs/xxl-job
      logretentiondays: 30
    accessToken: ${XXL_JOB_ACCESS_TOKEN}
```

### 4.3 XxlJobConfig 类

```java
@Configuration
public class XxlJobConfig {

    @Value("${xxl.job.admin.addresses}")
    private String adminAddresses;

    @Value("${xxl.job.executor.appname}")
    private String appname;

    @Value("${xxl.job.accessToken}")
    private String accessToken;

    @Value("${xxl.job.executor.port}")
    private int port;

    @Bean
    public XxlJobSpringExecutor xxlJobExecutor() {
        XxlJobSpringExecutor executor = new XxlJobSpringExecutor();
        executor.setAdminAddresses(adminAddresses);
        executor.setAppname(appname);
        executor.setAccessToken(accessToken);
        executor.setPort(port);
        executor.setLogPath("/data/logs/xxl-job");
        executor.setLogRetentionDays(30);
        return executor;
    }
}
```

## 8. 与其他服务的关系

| 上游 | 下游 | 关系 |
|------|------|------|
| XXL-JOB Admin | job（执行器） | 调度触发 |
| job | 各业务服务 | 通过 Dubbo/HTTP 执行任务 |

> **推荐做法**：各业务服务自带执行器（如 monitor-service 有自己的 metricsAggregateJob），spring-cloud-job 只做集中备份或独立的跨服务任务。

---

## 9. 实现要点

| 项 | 要点 |
|----|------|
| Cron 表达式 | Quartz 风格，6 必填 + 1 可选 |
| 任务分片 | 用 `ShardingUtil.getShardingVo()` 支持分片广播 |
| 任务日志 | `XxlJobHelper.log()` 写日志，Admin 可查 |
| 任务状态 | `handleSuccess()` / `handleFail()` |
| 失败重试 | Admin 配置 maxRetryCount，自动重试 |
| accessToken | 防止未授权执行器注册 |
| 防火墙 | 执行器端口 10009 不对公网开放 |
| 任务幂等 | 同一任务可能被调度多次，业务要幂等 |
