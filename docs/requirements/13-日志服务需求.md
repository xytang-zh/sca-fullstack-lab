# 13 · 日志服务需求（spring-cloud-log）

> 端口 8089，统一记录操作日志、登录日志、审计日志，存 MongoDB（按月分表）。

---

## 1. 模块定位

| 维度 | 值 |
|------|-----|
| 服务名 | `spring-cloud-log` |
| HTTP 端口 | 8089 |
| Dubbo 端口 | 20889 |
| 顶级包 | `com.xytang.log` |
| 启动类 | `SpringCloudLogApplication` |
| 角色 | 日志中心 |
| 依赖 | MongoDB、MySQL、RabbitMQ、Nacos |

---

## 2. 功能清单

### 2.1 操作日志模块

| 功能 | 描述 | 业务规则 |
|------|------|----------|
| 注解记录 | `@OperationLog` AOP 自动记录 | 来自 spring-cloud-common-log |
| 异步写入 | MQ 异步入库 | 不阻塞业务 |
| 入参出参 | 序列化为 JSON | 大字段截断 |
| 异常堆栈 | 记录失败原因 | |
| 慢操作标记 | >500ms 标记 | |
| 查询 | 按用户/时间/类型 | |

### 2.2 登录日志模块

| 功能 | 描述 | 业务规则 |
|------|------|----------|
| 登录成功 | 监听 `user.login` 事件 | 写 MongoDB |
| 登录失败 | 记录失败原因 | |
| 注销 | 监听 `user.logout` 事件 | |
| 查询 | 按用户/IP/时间 | |
| 异地登录 | 标记 | 与 auth-service 异地告警联动 |

### 2.3 审计日志模块

| 功能 | 描述 | 业务规则 |
|------|------|----------|
| 敏感操作 | 删除、修改权限、修改密码 | 必须记录 |
| 越权操作 | 监听 403 异常 | |
| 数据导出 | 监听 export 操作 | |
| 查询 | 按操作类型/用户/时间 | |

### 2.4 分表模块（ShardingSphere）

| 功能 | 描述 | 业务规则 |
|------|------|----------|
| 按月分表 | `log_operation_YYYYMM` | 写多查少 |
| 自动建表 | XXL-JOB 每月 25 号 | 下月表 |
| 历史归档 | 6 个月前移归档库 | XXL-JOB |
| TTL 清理 | 30 天前删除 | MongoDB TTL |

## 3. 数据模型

```javascript

{

  args: "{...}",             // 入参 JSON
  result: "{...}",            // 出参 JSON

  httpMethod: "POST",
```

### 3.2 MySQL 表（归档用）

```sql
CREATE TABLE log_operation_archive (
    id BIGINT PRIMARY KEY,
    user_id BIGINT,
    username VARCHAR(50),
    title VARCHAR(100),
    business_type VARCHAR(20),
    method VARCHAR(255),
    args TEXT,
    result TEXT,
    status TINYINT,
    error_msg VARCHAR(500),
    cost_ms INT,
    ip VARCHAR(50),
    url VARCHAR(255),
    http_method VARCHAR(10),
    trace_id VARCHAR(50),
    create_time DATETIME,
    INDEX idx_user_time (user_id, create_time),
    INDEX idx_time (create_time)
);
```

## 6. 关键业务流程

### 6.1 操作日志记录流程

```
1. 管理员 POST /api/system/users
2. system-service 的 UserController.create 方法
   - 注解 @OperationLog(title="用户管理", businessType=INSERT)
3. OperationLogAspect AOP 拦截：
   - 捕获入参 args
   - 执行业务
   - 捕获出参 result
   - 计算 costMs
4. 异步发 MQ log.operation
5. log-service 消费：
   - 写 MongoDB log_operation
   - 失败重试 3 次
6. 前端查 GET /logs/operations
```

### 6.2 登录日志记录流程

```
1. 用户登录成功
2. auth-service 发 MQ user.login（含 userId, ip, deviceType, ...）
3. log-service 消费：
   - 解析 UserAgent（浏览器、OS）
   - IP 转地区（IP2Region）
   - 写 MongoDB log_login
4. 失败重试 3 次
```

### 6.3 分表与归档流程

```
1. 每月 25 号 XXL-JOB 触发 createNextMonthTablesJob
   - 创建 log_operation_archive_YYYYMM
2. 每天凌晨 XXL-JOB 触发 archiveOldLogsJob
   - 6 个月前的 MongoDB 日志 → MySQL 归档表
3. MongoDB TTL 自动清理 30 天前
```

## 7. 配置文件

```yaml
server:
  port: 8089

spring:
  data:
    mongodb:
      uri: mongodb://127.0.0.1:27017/aurora_log
      auto-index-creation: true
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/aurora_log_archive
  rabbitmq:
    host: 127.0.0.1
    port: 5672

# 日志配置
logging:
  level:
    root: INFO
    com.xytang: DEBUG
    org.springframework.data.mongodb: WARN

# 归档配置
log:
  archive:
    enabled: true
    archive-months: 6          # 6 个月前归档
    cleanup-months: 30          # 30 天清理
    batch-size: 1000
```

## 9. 实现要点

| 项 | 要点 |
|----|------|
| 异步写入 | MQ 异步，不阻塞业务 |
| 大字段截断 | args/result 超过 10KB 截断 |
| 敏感数据脱敏 | 密码、Token 字段不打日志 |
| IP 转地区 | 用 IP2Region 离线库 |
| UserAgent 解析 | 用 ua-parser |
| TTL 索引 | MongoDB 自动清理 30 天前 |
| 分表 | ShardingSphere 按月分表（可选） |
| 失败重试 | Spring AMQP 3 次 + 死信队列 |
| traceId | 与 Gateway 链路追踪联动 |
