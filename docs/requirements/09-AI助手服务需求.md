# 09 · AI 助手服务需求（spring-cloud-ai）

> 端口 8085，基于 Spring AI + RAG 实现企业知识库问答 + 对话历史 + SSE 流式响应。

---

| 维度 | 值 |

## 3. 数据模型

### 3.1 PostgreSQL（pgvector）

```sql
CREATE EXTENSION IF NOT EXISTS vector;

-- 知识库表
CREATE TABLE ai_knowledge_base (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    description TEXT,
    owner_id BIGINT,
    members JSONB COMMENT '[{"userId":1,"role":"admin"}]',
    default_model VARCHAR(50),
    status TINYINT DEFAULT 1,
    create_time TIMESTAMP,
    update_time TIMESTAMP
);

-- 文档表
CREATE TABLE ai_document (
    id BIGSERIAL PRIMARY KEY,
    kb_id BIGINT REFERENCES ai_knowledge_base(id),
    file_name VARCHAR(255),
    file_path VARCHAR(500) COMMENT 'MinIO 路径',
    file_type VARCHAR(20) COMMENT 'pdf/md/txt/docx',
    file_size BIGINT,
    chunk_count INT DEFAULT 0,
    status VARCHAR(20) COMMENT 'PENDING/PROCESSING/READY/FAILED',
    error_msg TEXT,
    create_time TIMESTAMP,
    update_time TIMESTAMP
);

-- 文档分块表（含向量）
CREATE TABLE ai_document_chunk (
    id BIGSERIAL PRIMARY KEY,
    doc_id BIGINT REFERENCES ai_document(id),
    kb_id BIGINT,
    chunk_index INT,
    content TEXT,
    embedding vector(1024) COMMENT '通义千问 text-embedding-v3 是 1024 维',
    token_count INT,
    metadata JSONB,
    create_time TIMESTAMP
);

-- 向量索引（HNSW，性能优）
CREATE INDEX idx_chunk_embedding
ON ai_document_chunk USING hnsw (embedding vector_cosine_ops);

-- 按知识库查询
CREATE INDEX idx_chunk_kb ON ai_document_chunk (kb_id);
CREATE INDEX idx_chunk_doc ON ai_document_chunk (doc_id);
```

## 5. SSE 流式响应规范

### 5.1 请求

```
POST /api/ai/chat/stream
Content-Type: application/json
Accept: text/event-stream

{
  "conversationId": "uuid-xxx",
  "message": "请解释 RAG 是什么",
  "model": "qwen-max"
}
```

### 5.2 响应

```
data: {"type":"RETRIEVAL","docs":[{"docId":1,"title":"RAG 文档","snippet":"...","score":0.85}]}\n\n
data: {"type":"CHUNK","content":"RAG 是"}\n\n
data: {"type":"CHUNK","content":"检索增强"}\n\n
data: {"type":"CHUNK","content":"生成"}\n\n
data: {"type":"DONE","messageId":"xxx","tokens":150,"latencyMs":2300}\n\n
```

### 5.3 前端处理

```typescript
import { fetchEventSource } from '@microsoft/fetch-event-source';

fetchEventSource('/api/ai/chat/stream', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', 'Authorization': `Bearer ${token}` },
  body: JSON.stringify({ conversationId, message }),
  onmessage(e) {
    const data = JSON.parse(e.data);
    if (data.type === 'CHUNK') appendToUI(data.content);
    else if (data.type === 'RETRIEVAL') showRetrieval(data.docs);
    else if (data.type === 'DONE') closeStream();
  }
});
```

## 6. 关键业务流程

### 6.1 文档上传与向量化

```
1. 用户上传 PDF
   POST /ai/documents (multipart/form-data)
2. ai-service：
   - 上传原文件到 MinIO
   - 写 ai_document（status=PENDING）
   - 发 MQ doc.uploaded
3. 异步消费者：
   - 状态改 PROCESSING
   - 从 MinIO 读取文件
   - 用 PDF 解析器提取文本
   - TokenTextSplitter 分块（每块 500 token，重叠 50）
   - EmbeddingModel.embed() 向量化（1024 维）
   - 批量写 ai_document_chunk
   - 状态改 READY
4. 失败：状态改 FAILED，记录 error_msg
```

### 6.2 RAG 问答流程

```
1. 用户发消息
   POST /ai/chat/stream
2. ai-service：
   - 写 MongoDB ai_messages（role=user）
   - 构造 ChatClient.prompt()
   - 加 QuestionAnswerAdvisor（基于 pgvector 检索）
     - 用户问题 → EmbeddingModel.embed() → 向量
     - SELECT * FROM ai_document_chunk
       WHERE kb_id = ?
       ORDER BY embedding <-> '[vector]'
       LIMIT 5
     - 返回 Top-5 文档片段
   - 加 ChatMemoryAdvisor（多轮上下文）
   - 调用 ChatClient.stream() 流式生成
3. SSE 推回（CHUNK + RETRIEVAL + DONE）
4. 写 MongoDB ai_messages（role=assistant，含 retrievalDocs）
5. 更新会话标题（如第一轮，自动生成标题）
6. 发 MQ ai.message.created → search-service 索引
```

## 10. 实现要点

| 项 | 要点 |
|----|------|
| 文档解析 | PDF 用 Apache PDFBox，DOCX 用 Apache POI，MD/TXT 直接读 |
| 分块策略 | TokenTextSplitter，500 token 一块，重叠 50 |
| 向量维度 | 通义千问 1024 维，OpenAI 1536 维，按模型调整 |
| 向量索引 | HNSW（性能优），距离 cosine |
| Top-K 检索 | 默认 5，可配置 |
| 流式响应 | 用 SseEmitter 或 WebFlux |
| 上下文窗口 | ChatMemoryAdvisor 默认 10 轮 |
| 异常处理 | LLM 调用失败返回 ERROR 事件 |
| 限流 | 用户级 + IP 级，防止滥用 |
| 模型切换 | 通过 ChatClient.Builder 动态切换 |
