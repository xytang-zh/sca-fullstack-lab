# 08 · 工作流服务需求（spring-cloud-workflow）

> 端口 8084，基于 Warm-Flow 实现 4 类典型审批流程（请假、报销、合同审批、采购申请）。

---

## 1. 模块定位

| 维度 | 值 |
|------|-----|
| 服务名 | `spring-cloud-workflow` |
| HTTP 端口 | 8084 |
| Dubbo 端口 | 20884 |
| XXL-JOB 执行器端口 | 10002 |
| 顶级包 | `com.xytang.workflow` |
| 启动类 | `SpringCloudWorkflowApplication` |
| 角色 | 工作流引擎 + 4 类业务审批 |
| 依赖 | MySQL、Redis、Nacos、RabbitMQ、MinIO |

## 2. 功能清单

### 2.1 流程定义模块

| 功能 | 描述 | 业务规则 |
|------|------|----------|
| 导入 JSON | 上传流程定义 JSON | 校验 JSON 格式 |
| 可视化设计器 | 嵌入 warm-flow-designer | 拖拽节点 |
| 发布 | 流程定义生效 | 同 flow_code 已发布版本自动停用 |
| 停用 | 流程定义不可发起 | 进行中的实例不受影响 |
| 版本管理 | 同 flow_code 多版本 | v1.0.0、v1.0.1 |
| 复制 | 基于现有流程定义新建 | 便于改造 |

### 2.2 流程实例模块

| 功能 | 描述 | 业务规则 |
|------|------|----------|
| 发起流程 | 业务 ID + 流程定义 + 表单 | 生成 instance + 第一个 task |
| 撤销 | 申请人撤销 | 仅在未审批前可撤销 |
| 催办 | 推送待办人 | 发 MQ `task.remind` |
| 转办 | 当前任务转给他人 | 原 user 不再可见 |
| 委托 | 委托他人代办 | 完成后回原 user |
| 加签 | 增加审批人 | 同时或顺序 |
| 减签 | 移除审批人 | 仅管理员 |
| 流程图查看 | 显示当前节点 + 已走节点 | 高亮 |

### 2.3 任务模块

| 功能 | 描述 | 业务规则 |
|------|------|----------|
| 待办列表 | 当前用户待办 | 按 createTime DESC |
| 已办列表 | 当前用户已办 | 按完成时间 DESC |
| 我发起的 | 申请人发起的实例 | 按状态筛选 |
| 审批通过 | 当前节点通过 | 进入下一节点 |
| 驳回 | 驳回到指定节点 | 默认驳回到发起人 |
| 流程历史 | 实例完整流转记录 | 节点/审批人/时间/意见 |

### 2.6 合同审批业务模块

## 3. 数据模型

### 3.1 Warm-Flow 自带 7 张表

```
flow_definition     流程定义
flow_node           流程节点
flow_skip           节点跳转
flow_instance       流程实例
flow_task           待办任务
flow_his_task       历史任务
flow_user           任务权限
```

### 3.2 业务表

```sql
-- 请假业务表
CREATE TABLE biz_leave (
    id BIGINT PRIMARY KEY,
    flow_instance_id BIGINT COMMENT '流程实例 ID',
    applicant_id BIGINT COMMENT '申请人',
    leave_type VARCHAR(20) COMMENT 'SICK/PERSONAL/ANNUAL',
    start_date DATE,
    end_date DATE,
    days DECIMAL(4, 1),
    reason VARCHAR(500),
    attachment_id BIGINT COMMENT '附件 file_id',
    status VARCHAR(20) COMMENT 'PROCESSING/APPROVED/REJECTED/CANCELED',
    create_time DATETIME,
    update_time DATETIME,
    INDEX idx_applicant (applicant_id),
    INDEX idx_instance (flow_instance_id)
);

-- 报销业务表
CREATE TABLE biz_expense (
    id BIGINT PRIMARY KEY,
    flow_instance_id BIGINT,
    applicant_id BIGINT,
    expense_type VARCHAR(20) COMMENT 'TRAVEL/MEAL/OFFICE/OTHER',
    amount DECIMAL(10, 2),
    detail TEXT COMMENT 'JSON 明细',
    invoice_ids VARCHAR(500) COMMENT '发票 file_id 列表',
    status VARCHAR(20),
    create_time DATETIME,
    update_time DATETIME
);

-- 合同业务表
CREATE TABLE biz_contract (
    id BIGINT PRIMARY KEY,
    flow_instance_id BIGINT,
    drafter_id BIGINT,
    contract_no VARCHAR(50) UNIQUE,
    party_a VARCHAR(100),
    party_b VARCHAR(100),
    amount DECIMAL(15, 2),
    terms TEXT,
    contract_file_id BIGINT,
    status VARCHAR(20),
    create_time DATETIME,
    update_time DATETIME
);

-- 采购业务表
CREATE TABLE biz_purchase (
    id BIGINT PRIMARY KEY,
    flow_instance_id BIGINT,
    applicant_id BIGINT,
    items TEXT COMMENT 'JSON 物品列表',
    total_amount DECIMAL(15, 2),
    supplier VARCHAR(100),
    status VARCHAR(20),
    create_time DATETIME,
    update_time DATETIME
);
```

## 6. 关键业务流程

### 6.1 请假审批流程

```
1. 员工张三发起请假（3 天病假）
   - POST /workflow/leaves
   - 写 biz_leave
   - 调 Warm-Flow InsService.start(flowCode, businessId)
   - 生成 instance + 第一个 task（直属领导审批）
   - 发 MQ task.todo → message-service 推送 WebSocket

2. 直属领导李四登录 → 看到待办
   - GET /workflow/tasks/todo
   - 点击任务 → 查看表单
   - POST /workflow/tasks/{id}/approve（意见：同意）
   - 流程进入下一节点（HR 审批）
   - 发 MQ task.todo（HR）

3. HR 王五审批
   - 同上 → 流程进入归档节点
   - 流程实例状态变为 COMPLETED
   - biz_leave 状态变为 APPROVED

4. 任意节点可驳回
   - POST /workflow/tasks/{id}/reject（意见：资料不全）
   - 流程回到发起人
   - biz_leave 状态变为 REJECTED
```

### 6.2 催办流程

```
1. 申请人点"催办"
2. POST /workflow/instances/{id}/urge
3. 查当前 task 的处理人
4. 发 MQ task.remind
5. message-service 消费 → WebSocket 推送"您有新的待办催办"
```

## 8. 与其他服务的关系

| 上游 | 下游 | 关系 |
|------|------|------|
| Gateway | workflow | HTTP 转发 |
| workflow | system | Dubbo 查用户、部门 |
| workflow | file | HTTP 上传附件 |
| workflow | message | MQ `task.todo`、`task.remind` |
| workflow | log | MQ `log.operation` |
| workflow | Redis | 流程缓存 |

## 9. 实现要点

| 项 | 要点 |
|----|------|
| Warm-Flow 集成 | `warm-flow-mybatis-plus-sb3-starter:1.8.8` |
| 业务表关联 | 通过 `flow_instance_id` 关联业务表 |
| 动态表单 | 流程定义 JSON 中声明表单字段，前端动态渲染 |
| 流程图高亮 | 调 Warm-Flow API 获取已走节点，前端高亮 |
| 加签/减签 | 用 Warm-Flow 内置 node_ratio |
| 催办 | 发 MQ 事件，由 message-service 推送 |
| 撤销 | 仅在第一个节点未审批前可撤销 |
| 多实例会签 | Warm-Flow 内置支持 |
