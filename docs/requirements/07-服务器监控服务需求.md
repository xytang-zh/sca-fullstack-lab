# 07 · 服务器监控服务需求（spring-cloud-monitor）

> 端口 8083，采集服务器/JVM 指标，存时序库，通过 WebSocket 推送到前端大盘。

---

## 1. 模块定位

| 维度 | 值 |
|------|-----|
| 服务名 | `spring-cloud-monitor` |
| HTTP 端口 | 8083 |
| Dubbo 端口 | 20883 |
| WebSocket 端口 | 9090 |
| XXL-JOB 执行器端口 | 10001 |
| 顶级包 | `com.xytang.monitor` |
| 启动类 | `SpringCloudMonitorApplication` |
| 角色 | 服务器监控 + 告警中心 |
| 依赖 | TDengine、Redis、RabbitMQ、Nacos |

## 2. 功能清单

### 2.1 采集模块

| 功能 | 描述 | 实现要点 |
|------|------|----------|
| 本机指标采集 | CPU、内存、磁盘、网络、JVM | OSHI 6.6 |
| 接收 Agent 上报 | 接收其他服务的 monitor-agent 上报 | HTTP `/api/agent/report` |
| 采集频率 | 默认 5 秒 | 可配置 |
| 多服务多实例 | 每个微服务一个子表 | TDengine 超级表 |

### 2.2 存储模块

| 功能 | 描述 | 实现要点 |
|------|------|----------|
| TDengine 超级表 | `aurora_metrics` | 按 service_name + instance 标签 |
| 自动建子表 | INSERT 时自动建 | TDengine 特性 |
| 数据保留 | 90 天 | TDengine TTL 配置 |

### 2.3 推送模块

| 功能 | 描述 | 实现要点 |
|------|------|----------|
| WebSocket Server | Netty 端口 9090 | ChannelRouter 路由 |
| 用户订阅 | 按 `userId → Channel` 推送 | 一个用户多端在线 |
| 订阅过滤 | 用户可选订阅哪些服务 | 消息过滤 |

### 2.4 历史查询模块

| 功能 | 描述 | 实现要点 |
|------|------|----------|
| 时间范围查询 | 1h / 24h / 7d / 30d | TDengine SQL |
| 指标选择 | CPU/内存/磁盘/JVM/网络 | 多字段查询 |
| 服务选择 | 下拉框 | 按 service_name 分组 |
| 聚合 | AVG/MAX/MIN | 按 interval 聚合 |
| 降采样 | 大范围自动降采样 | 7d → 1min 聚合，30d → 5min |

### 2.5 告警模块

| 功能 | 描述 | 业务规则 |
|------|------|----------|
| 阈值规则 | CPU > 80%、内存 > 90% | Nacos 配置 |
| 告警去抖 | 同一指标 5 分钟内只告一次 | Redis 去重 |
| 告警分级 | INFO/WARN/CRITICAL | 按严重程度 |
| 告警通知 | 发 MQ `alert.trigger` | message-service 推送 |
| 告警恢复 | 指标恢复发 `alert.resolved` | 自动恢复 |
| 告警静默 | 维护期不告警 | 配置静默窗口 |

### 2.6 Prometheus 整合

| 功能 | 描述 |
|------|------|
| 暴露指标 | `/actuator/prometheus` |
| Prometheus 拉取 | 15s 一次 |
| Grafana 大盘 | 数据源接 Prometheus + TDengine |

## 3. 数据模型

### 3.1 TDengine 超级表

```sql
CREATE STABLE aurora_metrics (
    ts TIMESTAMP,
    cpu_usage DOUBLE,
    cpu_load DOUBLE,
    mem_total BIGINT,
    mem_used BIGINT,
    mem_usage DOUBLE,
    disk_total BIGINT,
    disk_used BIGINT,
    disk_usage DOUBLE,
    jvm_heap BIGINT,
    jvm_non_heap BIGINT,
    jvm_thread_count INT,
    jvm_gc_count BIGINT,
    jvm_gc_time BIGINT,
    network_in BIGINT,
    network_out BIGINT
) TAGS (
    service_name VARCHAR(64),
    instance VARCHAR(128),
    env VARCHAR(20)
);

-- 子表自动创建
INSERT INTO aurora_metrics
USING aurora_metrics
TAGS ('spring-cloud-system', '192.168.1.10:8082', 'prod')
VALUES (NOW, 0.32, 0.65, ...);

-- 查询：最近 1 小时 CPU 平均
SELECT AVG(cpu_usage) FROM aurora_metrics
WHERE service_name = 'spring-cloud-system' AND ts > NOW - 1h;
```

### 3.2 MySQL 表

```sql
-- 告警规则表
CREATE TABLE biz_alert_rule (
    id BIGINT PRIMARY KEY,
    rule_name VARCHAR(100) NOT NULL,
    service_name VARCHAR(64),
    metric VARCHAR(50) COMMENT 'cpu_usage/mem_usage/...',
    operator VARCHAR(10) COMMENT '>/</>=/<=',
    threshold DOUBLE,
    duration INT COMMENT '持续 N 秒',
    severity TINYINT COMMENT '1=INFO 2=WARN 3=CRITICAL',
    enabled TINYINT DEFAULT 1,
    create_time DATETIME,
    update_time DATETIME
);

-- 告警记录表
CREATE TABLE biz_alert_record (
    id BIGINT PRIMARY KEY,
    rule_id BIGINT,
    service_name VARCHAR(64),
    metric VARCHAR(50),
    current_value DOUBLE,
    threshold DOUBLE,
    severity TINYINT,
    status TINYINT COMMENT '1=活跃 2=已恢复 3=已静默',
    triggered_at DATETIME,
    resolved_at DATETIME,
    INDEX idx_service_status (service_name, status)
);
```

### 3.3 Redis Key

| Key | 类型 | TTL | 说明 |
|-----|------|-----|------|
| `monitor:alert:{service}:{metric}` | String | 5min | 告警去抖 |
| `monitor:silence:{service}` | String | 静默时长 | 维护期静默 |
| `monitor:subscribe:{userId}` | Set | - | 用户订阅的服务列表 |

## 5. WebSocket 协议

### 5.1 握手

```
ws://localhost:8080/ws/monitor/10001?token=xxx
```

服务端校验 Token 后绑定到 Channel。

### 5.2 消息格式

```json
// 服务端推送：实时指标
{
  "type": "METRIC",
  "to": "10001",
  "content": {
    "serviceName": "spring-cloud-system",
    "instance": "192.168.1.10:8082",
    "metrics": { "cpu_usage": 0.32, ... },
    "timestamp": 1722470400000
  }
}

// 服务端推送：告警
{
  "type": "ALERT",
  "to": "10001",
  "content": {
    "ruleName": "CPU 高",
    "service": "spring-cloud-system",
    "metric": "cpu_usage",
    "value": 0.92,
    "threshold": 0.8,
    "severity": 3,
    "triggeredAt": "2026-07-29 10:00:00"
  }
}

// 客户端订阅
{ "type": "SUBSCRIBE", "services": ["spring-cloud-system", "spring-cloud-auth"] }

// 客户端心跳
{ "type": "PING" }
// 服务端响应
{ "type": "PONG" }
```

## 7. 关键业务流程

### 7.1 指标采集与推送

```
1. 各业务服务内置 monitor-agent，5s 采集一次本机指标
2. Agent POST /api/agent/report 上报
3. monitor-service：
   - 接收数据
   - 写 TDengine 超级表
   - 检查告警规则（命中发 MQ）
   - 推送到 WebSocket 订阅用户
4. 前端大盘实时刷新
```

### 7.2 告警流程

```
1. monitor-service 每秒扫描最新指标
2. 命中阈值规则（如 CPU > 80%）
3. Redis 去抖：monitor:alert:system:cpu_usage 是否存在
   - 存在：跳过（5 分钟内已告警）
   - 不存在：写入（TTL 5min）
4. 写 biz_alert_record 表
5. 发 MQ alert.trigger
6. message-service 消费 → WebSocket 推送 + 邮件/短信
7. 指标恢复 → 发 alert.resolved
```

## 8. 配置文件

```yaml
server:
  port: 8083

spring:
  datasource:
    driver-class-name: com.taosdata.jdbc.rs.RestfulDriver
    url: jdbc:TAOS-RS://127.0.0.1:6041/aurora_monitor?user=root&password=taosdata

spring-cloud:
  netty:
    port: 9090

# OSHI 配置
oshi:
  init-timeout: 5s

# 告警规则（Nacos）
monitor:
  alert:
    enabled: true
    scan-interval: 1s
    debounce-ttl: 5m
    rules:
      - name: CPU 高
        metric: cpu_usage
        operator: '>'
        threshold: 0.8
        duration: 60
        severity: 3
      - name: 内存高
        metric: mem_usage
        operator: '>'
        threshold: 0.9
        duration: 60
        severity: 3
      - name: JVM 堆高
        metric: jvm_heap_usage
        operator: '>'
        threshold: 0.85
        duration: 300
        severity: 2
```

## 9. 与其他服务的关系

| 上游 | 下游 | 关系 |
|------|------|------|
| 所有业务服务 | monitor | Agent 上报（HTTP） |
| monitor | message | MQ `alert.trigger`（告警推送） |
| monitor | system | Dubbo 查用户（告警通知对象） |
| monitor | TDengine | 指标存储 |
| monitor | Redis | 告警去抖 |
| Prometheus | monitor | 拉取 `/actuator/prometheus` |
| Grafana | monitor + Prometheus | 大盘可视化 |

## 10. 实现要点

| 项 | 要点 |
|----|------|
| OSHI 实例化 | 单例 SystemInfo，避免重复初始化 |
| TDengine 连接 | 用 RESTful Driver（`jdbc:TAOS-RS`），避免原生依赖 |
| TDengine 时区 | JVM 与 DB 时区一致，避免时间错位 |
| WebSocket 多端 | 一个 userId 多 Channel，遍历推送 |
| 心跳机制 | 30s PING，60s 无响应关闭 |
| 告警去抖 | Redis SETNX + TTL |
| 历史查询降采样 | 大范围自动聚合，避免返回百万数据点 |
| Prometheus 指标 | 与 TDengine 互补：Prometheus 存系统指标，TDengine 存业务指标 |
