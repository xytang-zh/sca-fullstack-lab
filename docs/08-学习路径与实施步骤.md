# 08 · 学习路径与实施步骤

> 本文给出一份 **新手友好的 13 周学习路径** + **实施步骤清单**。
> 每周聚焦 1-2 个技术点，循序渐进，最终把整个项目跑起来。

---

## 8.1 学习原则

1. **先跑起来再深入**：第一周目标只有一个——把项目骨架立起来、能 `mvn clean package`、能 `docker compose up`。
2. **垂直切片**：每完成一个功能，要打通"前端 → 网关 → 后端 → 数据库"全链路，而不是先把所有后端做完再做前端。
3. **不要追求完美**：本项目是学习用，生产级稳定性、性能、安全可以后期迭代。
4. **写博客**：每周写一篇总结（Markdown 即可），13 周后就有 13 篇博客，简历亮点直接成型。
5. **善用工具**：Arthas（线上诊断）、jstack/jmap、EXPLAIN、Kibana、Spec-Kit——这些工具越早用越熟。
6. **先用 Spec-Kit 写规格，再写代码**：每个功能先用 SDD 流程产出 `spec.md → plan.md → tasks.md`，再让 AI 按任务实现。

## 8.2 第 0 周（前置准备）：Spec-Kit SDD 工作流

**目标**：在仓库里初始化 GitHub Spec-Kit，体验"规格驱动开发"流程，为后续每周的功能开发打基础。

**技术点**：
- GitHub Spec-Kit（`github/spec-kit`）
- AI 辅助 SDD 命令链：`/speckit.specify` → `/speckit.plan` → `/speckit.tasks` → `/speckit.implement`

**任务清单**：
- [ ] 阅读仓库 `github/spec-kit` 的 README 与 `spec-driven.md`
- [ ] 在 `aurora-backend` 仓库根目录初始化 Spec-Kit（按官方文档安装 CLI 或作为 Claude Code / Cursor 的 slash 命令）
- [ ] 用 `/speckit.specify` 写第一个规格：`specs/000-mvp-user-crud/spec.md`（用于第 1 周的用户管理）
- [ ] 用 `/speckit.plan` 生成 `plan.md`、`data-model.md`、`contracts/`
- [ ] 用 `/speckit.tasks` 生成 `tasks.md`，看任务如何被自动并行/串行分组
- [ ] 体验 `/speckit.implement`：让 AI 按任务清单实现一部分（不要求跑完，感受流程）
- [ ] 写博客《Spec-Driven Development 入门：GitHub Spec-Kit 实践》

**产出**：
- `specs/` 目录有第一份规格文档
- 后续每周开新功能前，都先走一遍 SDD 流程

> 💡 **学习心法**：Spec-Kit 不会让你"少写代码"，但会让你"少写废代码"。
> 它的最大价值是逼你先想清楚"要做什么"，再让 AI 帮你"怎么实现"。

## 8.3 后端代码骨架初始化命令

```bash
# 1. 创建项目根目录
mkdir aurora-backend && cd aurora-backend
git init

# 2. 初始化父 POM（手写或用 Maven archetype）
cat > pom.xml << 'EOF'
<project xmlns="http://maven.apache.org/POM/4.0.0">
  <modelVersion>4.0.0</modelVersion>
  <groupId>com.aurora</groupId>
  <artifactId>aurora-backend</artifactId>
  <version>1.0.0-SNAPSHOT</version>
  <packaging>pom</packaging>
  <modules>
    <module>aurora-common</module>
    <module>aurora-gateway</module>
    <module>aurora-auth</module>
    <module>aurora-services</module>
    <module>aurora-starters</module>
  </modules>
</project>
EOF

# 3. 创建子模块（示例）
mkdir -p aurora-common/aurora-common-core
mkdir -p aurora-services/aurora-system
# ...

# 4. 创建前端
mkdir aurora-admin && cd aurora-admin
pnpm create vite . --template vue-ts
pnpm add naive-ui pinia vue-router@4 axios unocss
```

## 8.7 排坑清单（按周对应）

| 周 | 常见坑 | 解决 |
|----|--------|------|
| 0 | Spec-Kit 命令找不到 | 确认安装路径，Claude Code / Cursor 已识别 slash 命令 |
| 1 | Maven 依赖冲突 | `mvn dependency:tree` 看依赖树 |
| 2 | Sa-Token 跨域失败 | 后端 CORS + 前端 withCredentials |
| 3 | Nacos 配置不生效 | bootstrap.yml 引导依赖 + 配置文件后缀 |
| 4 | SSO 跳转死循环 | 检查 Server / Client 的 allowUrls |
| 5 | Redis 大 Key | 用 `--bigkeys` 扫描 |
| 6 | Dubbo 调用超时 | 默认 1s，调整 timeout |
| 6 | MQ 消费幂等 | 用 messageId + Redis 去重 |
| 7 | Warm-Flow 节点权限 | 检查 `flow_user` 表 |
| 8 | TDengine 时区 | JVM 时区与 DB 一致 |
| 8 | Prometheus 拉不到指标 | 检查 `management.endpoints.web.exposure.include` |
| 8 | Grafana 大盘空白 | 检查数据源 + 时间范围 + 标签匹配 |
| 9 | Spring AI 流式响应 | 用 WebFlux 或 SseEmitter |
| 10 | ES 分词不生效 | 字段类型必须是 text，且 ik_max_word |
| 11 | WebSocket 跨域 | Netty 加 `setHandshakeHandler` 处理 Origin |
| 12 | ShardingSphere 全表扫描 | 查询必须带分片键 |
| 12 | ShardingSphere DDL 失败 | 不支持自动 DDL，需定时建表 |
| 12 | 国产库 SQL 报错 | 检查保留字、类型映射、私有函数 |
| 13 | XXL-JOB 执行器注册不上 | 检查 accessToken、防火墙、appname |
| 13 | JimuReport 数据源连不上 | 检查 firewall 配置 + 数据源白名单 |
| 13 | Docker 网络隔离 | 用 docker network create aurora-net |

## 8.9 学习心法

1. **每周复盘**：周日花 1 小时写总结，比埋头写 7 天代码更有效。
2. **多看源码**：每周抽 2 小时读 Spring / Sa-Token 源码，理解"为什么这么设计"。
3. **多画图**：架构图、时序图、流程图——画图 = 思考。
4. **多问"为什么"**：每个技术点都问一句"为什么不这么做？"——你会发现很多坑。
5. **善用 git 分支**：每周一个 feature 分支，回头 merge。这样进度可视、可回退。
