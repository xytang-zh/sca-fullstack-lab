### 2.2.2 Sa-Token 1.44.0（dromara 出品）

来源：context7 /dromara/sa-token 官方文档

**核心能力**：
- 登录认证、权限认证、会话治理
- **SSO 单点登录**：三种模式
  - 模式一：**同 Redis 共享会话**（最简单，子系统用同一 Redis）
  - 模式二：**Server 授权、Client 校验**（推荐，跨域）
  - 模式三：**前端跨域携 Token**（适用于前后端分离 + 多端）
- **踢人下线**：基于 deviceId 标识设备，可精准踢下线指定设备
- **OAuth2.0**：内置授权码、客户端凭证等模式
- **微服务网关鉴权**：网关统一拦截，子服务用 Sa-Token Context 透传

**关键 API**：

```java
// 登录并绑定设备ID
StpUtil.login(10001, new SaLoginParameter().setDeviceId(deviceId));

// 踢人下线
StpUtil.kickout(10001, "PC");

// SSO Server 端
SaSsoServerUtil.ssoLogout(loginId); // 单点注销

// SSO Client 端
SaSsoClientProcessor.instance.dister(); // 处理所有 SSO 请求
```

### 2.2.5 MyBatis-Plus + dynamic-datasource

来源：context7 /baomidou/mybatis-plus-doc 与 /baomidou/dynamic-datasource

**MyBatis-Plus 核心能力**：
- 通用 CRUD（BaseMapper）
- 条件构造器（LambdaQueryWrapper）
- 分页插件（PaginationInnerInterceptor）
- 多租户插件（TenantLineInnerInterceptor）
- 代码生成器（mybatis-plus-generator）

**dynamic-datasource 核心能力**：
- `@DS("master")` / `@DS("slave")` 注解切换数据源
- `@DSTransactional` 跨数据源事务
- 支持数据源分组、读写分离
- 支持 `Seata` 集成做分布式事务

**示例**：

```java
@Service
public class UserService {
    @DS("master")
    public User getById(Long id) { ... }

    @DS("kingbase")  // 国产库
    public List<User> listKB() { ... }
}
```

### 2.2.6 Redisson 4.0.0（或 3.x stable）

来源：context7 /redisson/redisson

**核心能力**：
- 分布式锁：`RLock`、`RedLock`（争议算法，慎用）
- 限流：`RRateLimiter`
- 延迟队列：`RDelayedQueue`
- 分布式集合：`RMap`、`RSet`、`RQueue`
- Spring Cache 集成：`@Cacheable` 走 Redisson

> ⚠️ **版本建议**：Redisson 4.0.0 是最新版，但 3.x 系列在生产更成熟。
> 建议学习用 4.0.0，生产部署用 3.42+。

### 2.2.7 Caffeine 多级缓存

**多级缓存架构**：

```
请求 → Caffeine（L1，本地） → Redis（L2，远程） → DB
                ↑                            |
                +——— 缓存回写 ←——————————————+
```

**实现方式**：
- Spring Cache 抽象 + Caffeine + Redisson 组合
- 或参考 `lifecycle-cache`、`layered-cache` 等开源实现

### 2.2.8 Netty + WebSocket

**为什么用 Netty 而不是 Spring WebSocket**：
- Netty 更底层，可控性强，性能高
- 适合做 **百万级连接** 的网关（如监控、IM）
- Spring WebSocket（基于 Tomcat）适合中等规模场景

**学习要点**：
- `EventLoopGroup`、`ChannelPipeline`、`ChannelHandler`
- WebSocket 协议握手、心跳、断线重连
- 与 Spring Boot 集成：`@Component` + `CommandLineRunner` 启动 Netty Server

### 2.2.9 多数据库适配（人大金仓 / 达梦）

| 国产库 | 兼容性 | JDBC 驱动 |
|--------|--------|-----------|
| 人大金仓 KingbaseES V8 | 兼容 PostgreSQL 协议 | `kingbase8.jar` |
| 达梦 DM8 | 兼容 Oracle 语法 | `DmJdbcDriver18.jar` |

**适配要点**：
1. 用 `dynamic-datasource` 配置多个 DataSource
2. MyBatis-Plus 的 `DbType` 枚举支持 `KINGBASE_ES`、`DM`
3. SQL 写法上避免 MySQL 私有函数（如 `GROUP_CONCAT`），改用标准 SQL
4. 字段类型映射：`tinyint` → `smallint`，`datetime` → `timestamp`

### 2.2.10 前端选型说明

**为什么选 Naive UI 而不是 Element Plus**：
- Naive UI：TypeScript 原生支持、暗黑模式原生、主题定制灵活
- Element Plus：生态更广，但类型支持略弱
- 两者都很好，本项目选 Naive UI 是为了与 UnoCSS 配合更顺

**为什么选 UnoCSS 而不是 Tailwind**：
- UnoCSS 引擎更快（即时按需生成）
- attributify mode（属性式写法）：`<div text="sm gray-500" font="bold">`
- 与 Naive UI 共存冲突少

### 2.2.11 GitHub Spec-Kit（规格驱动开发 / SDD）

来源：context7 `/github/spec-kit` 官方文档

**Spec-Kit 是什么**：
- GitHub 官方开源的 **AI 辅助规格驱动开发（Spec-Driven Development, SDD）** 工具包
- 它不是运行时依赖，而是 **开发方法论工具**：把"需求 → 设计 → 任务 → 实现"四步结构化
- 让 AI 编码助手（Claude Code / Cursor / Copilot）按结构化文档逐步落地，而非"凭直觉写代码"

**核心命令链**（在你的代码仓库里执行）：

| 命令 | 产出 | 用途 |
|------|------|------|
| `/speckit.specify <需求描述>` | `specs/<feature>/spec.md` | 写规格：用户故事、约束、验收标准 |
| `/speckit.plan <技术栈说明>` | `specs/<feature>/plan.md` + `data-model.md` + `contracts/` + `research.md` | 设计：架构、数据模型、接口契约、技术调研 |
| `/speckit.tasks` | `specs/<feature>/tasks.md` | 把 plan 拆成可执行任务清单，自动标记并行/串行 |
| `/speckit.implement [范围]` | 实际代码 | AI 按 tasks.md 顺序实现，可分阶段 |
| `/speckit.review` | review 报告 | 代码审查与规格一致性检查 |

**项目用法示例**：

```bash
# 在仓库根目录初始化 Spec-Kit
/speckit.specify 实现 SSO 单点登录，支持 Sa-Token 模式二、踢人下线、Refresh Token

# 自动产出：
# specs/001-sso/spec.md（含用户故事、流程、边界条件）

/speckit.plan 用 Sa-Token 1.44 + Spring Cloud Gateway，Redis 存会话，前端 Vue3

# 自动产出：
# specs/001-sso/plan.md（架构决策）
# specs/001-sso/data-model.md（sys_user 表设计）
# specs/001-sso/contracts/（OAuth2 接口契约）
# specs/001-sso/research.md（Sa-Token 三模式对比）

/speckit.tasks
# 自动产出：specs/001-sso/tasks.md（30 个可执行任务，标记了哪些可并行）

/speckit.implement 先实现 Setup 与基础 CRUD 阶段，停在用户故事前
```

**与本项目的关系**：
- 本项目的 **每个微服务** 都建议先用 Spec-Kit 走一遍 SDD 流程，再开始写代码
- 这样产出的 `specs/` 目录本身就是项目文档，便于回顾与简历展示
- 见 `docs/08-学习路径与实施步骤.md` 第 0 周（前置准备）

### 2.2.12 XXL-JOB 3.5.0（分布式任务调度）

来源：context7 `/xuxueli/xxl-job` 官方文档

**核心架构**：
- **调度中心（xxl-job-admin）**：Web 管理台，负责任务调度、日志、监控，独立部署
- **执行器（Executor）**：业务服务集成 `xxl-job-core`，注册到调度中心
- **任务（Job）**：用 `@XxlJob("demoJobHandler")` 注解定义

**Maven 依赖**（业务服务侧）：

```xml
<dependency>
    <groupId>com.xuxueli</groupId>
    <artifactId>xxl-job-core</artifactId>
    <version>3.5.0</version>
</dependency>
```

**执行器配置**：

```properties
xxl.job.admin.addresses=http://xxl-job-admin:8080
xxl.job.executor.appname=aurora-system
xxl.job.executor.accessToken=secret
xxl.job.executor.port=9999
```

**Java 配置类**：

```java
@Configuration
public class XxlJobConfig {
    @Bean
    public XxlJobSpringExecutor xxlJobExecutor(
            @Value("${xxl.job.admin.addresses}") String adminAddresses,
            @Value("${xxl.job.executor.appname}") String appname,
            @Value("${xxl.job.executor.accessToken}") String accessToken,
            @Value("${xxl.job.executor.port:0}") int port) {
        XxlJobSpringExecutor executor = new XxlJobSpringExecutor();
        executor.setAdminAddresses(adminAddresses);
        executor.setAppname(appname);
        executor.setAccessToken(accessToken);
        executor.setPort(port);
        return executor;
    }
}
```

**任务示例**：

```java
@Component
public class SampleJob {
    @XxlJob("syncArticleToEs")
    public void syncArticleToEs() {
        XxlJobHelper.log("开始同步文章到 ES...");
        // 业务逻辑
        XxlJobHelper.handleSuccess("同步完成");
    }
}
```

**Cron 表达式**（Quartz 风格，6 必填 + 1 可选）：

| 字段 | 范围 | 特殊字符 |
|------|------|----------|
| 秒 | 0-59 | `, - * /` |
| 分 | 0-59 | `, - * /` |
| 时 | 0-23 | `, - * /` |
| 日 | 1-31 | `, - * ? / L W` |
| 月 | 1-12 | `, - * /` |
| 周 | 1-7 | `, - * ? / L #` |
| 年（可选） | 1970-2199 | `, - * /` |

**与 Quartz 对比**：

| 维度 | Quartz | XXL-JOB |
|------|--------|---------|
| 部署 | 嵌入业务 | 独立调度中心 + 业务执行器 |
| 可视化 | 无 | Web 管理台 |
| 集群 | 数据库锁 | 调度中心集群 + 分布式任务路由 |
| 任务失败重试 | 手动 | 内置 |
| 任务分片 | 不支持 | 内置 `ShardingUtil` |
| 学习成本 | 低 | 中 |

> 本项目第 6 周改为 XXL-JOB（替代原 Quartz 方案）。

### 2.2.13 Apache ShardingSphere 5.5.x（分库分表）

来源：context7 `/apache/shardingsphere` 官方文档

**核心模式**：
- **ShardingSphere-JDBC**：JDBC 增强层，业务无感知（推荐）
- **ShardingSphere-Proxy**：独立数据库代理
- 本项目用 **JDBC 模式**

**适用场景**：
- 单表数据量 > 1000 万、查询性能下降
- 历史数据归档（如订单按月分表）
- 多租户隔离（按租户分库）

**Spring Boot 集成**：

```properties
# Driver 改为 ShardingSphere
spring.datasource.driver-class-name=org.apache.shardingsphere.driver.ShardingSphereDriver
# 配置文件位置
spring.datasource.url=jdbc:shardingsphere:classpath:sharding/config.yaml
```

**分片规则配置**（`config.yaml`）：

```yaml
dataSources:
  ds_0:
    dataSourceClassName: com.zaxxer.hikari.HikariDataSource
    jdbcUrl: jdbc:mysql://127.0.0.1:3306/aurora_order_0
    username: root
    password: xxx
  ds_1:
    dataSourceClassName: com.zaxxer.hikari.HikariDataSource
    jdbcUrl: jdbc:mysql://127.0.0.1:3306/aurora_order_1
    username: root
    password: xxx

rules:
  - !SHARDING
    tables:
      t_order:
        actualDataNodes: ds_${0..1}.t_order_${202501..202512}
        tableStrategy:
          standard:
            shardingColumn: order_date
            shardingAlgorithmName: order_month_alg
        databaseStrategy:
          standard:
            shardingColumn: user_id
            shardingAlgorithmName: user_db_alg
    shardingAlgorithms:
      user_db_alg:
        type: INLINE
        props:
          algorithm-expression: ds_${user_id % 2}
      order_month_alg:
        type: INTERVAL
        props:
          sharding-pattern: yyyyMM
```

**本项目分表场景**（见 06 章）：
- `biz_operation_log`：按月分表（数据量大、查询少）
- `biz_login_log`：按月分表
- `biz_order`：按 user_id 分库 + 按月分表（如果有电商业务）

### 2.2.14 Prometheus + Grafana（指标监控可视化）

**Prometheus**：
- 时序数据库 + 拉取式采集（业务暴露 `/actuator/prometheus`，Prom 主动拉）
- 查询语言 PromQL
- 与 Spring Boot 集成：`micrometer-registry-prometheus`

**Grafana**：
- 大盘可视化工具
- 支持 Prometheus、ES、TDengine、Loki 等数据源
- 丰富的社区仪表盘（Dashboard ID 直接 import）

**Spring Boot 集成**：

```xml
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-registry-prometheus</artifactId>
</dependency>
```

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,info,prometheus,metrics
  metrics:
    tags:
      application: ${spring.application.name}
```

**架构**：

```
微服务暴露 /actuator/prometheus
            ↓
       Prometheus（拉取，15s）
            ↓
       时序存储
            ↓
       Grafana（查询 + 可视化）
```

**与 TDengine 的分工**：
- TDengine 存"业务监控"（CPU、JVM、自定义业务指标）
- Prometheus 存"系统指标"（HTTP QPS、P99 延迟、JVM GC）
- 两者互补，Grafana 可同时挂两个数据源

### 2.2.15 JimuReport 2.3.4（低代码报表）

来源：context7 `/jeecgboot/jimureport` 官方文档

**核心能力**：
- 在线报表设计器（类积木拼接）
- 支持复杂报表、打印、大屏、仪表盘
- 支持 30+ 数据源（MySQL、PG、Oracle、SQL Server、KingbaseES、MongoDB、Redis 等）
- 提供 SpringBoot 3 Starter

**Maven 依赖**：

```xml
<dependency>
    <groupId>org.jeecgframework.jimureport</groupId>
    <artifactId>jimureport-spring-boot3-starter</artifactId>
    <version>2.3.4</version>
</dependency>
<!-- 按需引入 NoSQL / 文件数据集支持 -->
<dependency>
    <groupId>org.jeecgframework.jimureport</groupId>
    <artifactId>jimureport-nosql-starter3</artifactId>
    <version>2.3.0</version>
</dependency>
<!-- 按需引入 ECharts 图表支持 -->
<dependency>
    <groupId>org.jeecgframework.jimureport</groupId>
    <artifactId>jimureport-echarts-starter</artifactId>
    <version>2.3.0</version>
</dependency>
```

**配置**：

```yaml
jeecg:
  jmreport:
    firewall:
      dataSourceSafe: false
      lowCodeMode: prod
      sqlInjectionLevel: basic
    col: 100
    row: 200
    max-data-rows: 100000
```

**部署模型**：

```
SpringBoot Application (port 8085)
├── JimuReport UI（静态资源，Web 设计器）
├── JimuReport APIs（/jmreport/*, /drag/*）
├── 认证层（Sa-Token 集成）
├── 报表引擎（渲染、打印、导出）
├── 数据源管理（连接池、SQL 执行）
└── 文件存储（local、MinIO、阿里云 OSS）
```

**本项目使用场景**：
- **aurora-report 服务**：嵌入 JimuReport，提供报表设计器入口
- 业务报表：用户增长、订单统计、流程审批时长分析
- 监控大屏：服务器 CPU/内存/磁盘趋势图（数据来自 TDengine）
- 数据导出：报表 → Excel / PDF
