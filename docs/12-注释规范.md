# 注释规范（Commenting Convention）

> 本文档面向 AI 编码助手（Claude Code / Codex / Cursor），用于为项目代码**补充/生成注释**时统一遵循的规范。
> 适用范围：`sca-fullstack-lab`
> 全仓库所有代码文件（Java、TypeScript/JavaScript、Vue、HTML、CSS/SCSS/SASS、XML、YAML、SQL、Dockerfile、Shell、Markdown）。
> 工作前**必须**先读取仓库根 [`sca-fullstack-lab/CLAUDE.md`](../CLAUDE.md)、对应子项目的 [
`spring-cloud-alibaba/CLAUDE.md`](../spring-cloud-alibaba/CLAUDE.md) 与 [
`vue-web-ui/CLAUDE.md`](../vue-web-ui/CLAUDE.md)。
> 依赖文档：`docs/01-项目概述.md`、`docs/04-服务架构设计.md`、`docs/10-IDEA与工程结构.md`。

## 1. 总则（先读）

### 1.1 为什么本项目需要注释

本项目是**学习向项目**，目的是在实战中学习并理解各个技术和框架。因此注释不只是"锦上添花"，而是**项目资产的一部分**：

- 帮助读者理解**框架运行原理**（如 Spring 的 AOP 代理、Sa-Token 的过滤器链、Vue 的响应式）
- 帮助读者理解**业务设计意图**（如"为什么这里用分布式锁"、"为什么 Redis Key 这样命名"）
- 帮助读者理解**非显而易见的约束**（如"为什么这里必须用 Argon2id"、"为什么 ID 要转 String"）

### 1.2 注释的黄金法则

| 法则                    | 说明                        | 反例                              |
|-----------------------|---------------------------|---------------------------------|
| **注释解释 Why，不解释 What** | 代码本身表达"做了什么"，注释解释"为什么这么做" | `// 定义一个变量`（废话）                 |
| **注释解释"非显而易见"**       | 只有不读代码就不知道的才写             | `// i 加 1`（废话）                  |
| **注释与代码同步更新**         | 改了代码必须同步改注释，注释过期比没有更糟     | 注释说"返回 0 表示成功"，代码却返回 200        |
| **用中文注释**             | 与项目语言一致（仓库内注释均为中文）        | 中英混排                            |
| **好命名 > 注释**          | 能用命名表达清楚的不写注释             | `// 获取用户 id` 不如命名 `getUserId()` |
| **注释给出"上下文"**         | 说明前置条件、边界、调用方、影响面         | 只在方法里写 `// 逻辑`                  |

枚举类、常量类必须要有注释，其中的每个常量、枚举、方法也必须有注释**
所有类、接口中的方法都需要有方法注释，常量也必须要有注释**

### 1.3 注释语言

- **一律使用简体中文**，代码标识符、英文专有名词（如 `AOP`、`MVCC`、`Idempotent`）保留原文。
- 首次出现的中文术语可附英文原文，如 `熔断（Circuit Breaker）`。
- **禁止**使用拼音注释、中英混排的句子。

### 1.4 注释的"密度"要求

本项目是学习向项目，建议**注释密度高于常规企业项目**：

| 注释级别 | 覆盖率要求 | 适用场景                     |
|------|-------|--------------------------|
| 必须   | 100%  | 公开类、公开方法、公开接口、配置项、复杂业务逻辑 |
| 应当   | 80%+  | 私有方法、非平凡字段、分支逻辑、临时处理     |
| 禁止   | 0%    | 显而易见的一行代码、命名已自解释的调用      |

## 2. 注释类型总览（核心决策表）

### 2.1 类型定义

| 类型                         | 语法来源                                                               | 形态               | 用途                                    |
|----------------------------|--------------------------------------------------------------------|------------------|---------------------------------------|
| **文档注释**（Doc Comment）      | Java `/** */`、TS `/** */`、SCSS `///`                               | 多行，可被工具生成 API 文档 | 类、方法、函数、接口、类型、常量、公开成员                 |
| **独立行块注释**（Block Comment）  | Java `/* */`、TS `/* */`、CSS `/* */`、HTML `<!-- -->`、XML `<!-- -->` | 多行，独占一行或多行       | 文件名、复杂算法、模板区块、SQL 分组                  |
| **单行注释**（Line Comment）     | Java `//`、TS `//`、SCSS `//`、YAML `#`、SQL `--`                      | 单行、独占一行          | 业务步骤、分支逻辑、局部变量说明                      |
| **行尾注释**（Trailing Comment） | 各语言单行注释紧跟代码末尾                                                      | 单行、与代码同行         | 配置项含义、常量值、魔法数字、字段说明                   |
| **标签注释**（Tag Comment）      | 各语言单行注释 + 标签                                                       | 单行               | `TODO`、`FIXME`、`WARN`、`HACK`、`XXX` 待办 |
| **多媒体注释**（Rich Comment）    | Markdown 通用                                                        | 多行               | 补充 ASCII 图、时序图、示例、外部链接                |

### 2.2 场景 → 注释类型 决策表（**最重要，AI 必须优先遵循**）

| 场景                       | 注释类型                       | 示例                                               |
|--------------------------|----------------------------|--------------------------------------------------|
| 文件顶部说明（用途、所在模块、依赖）       | 文档注释 / 块注释                 | Java 类注释、TS 文件头、Vue 顶部注释                         |
| 类 / 接口 / 枚举 / 类型定义       | 文档注释                       | Java `/** 用户服务接口 */`                             |
| 公开方法 / 函数 / 组合式函数        | 文档注释（含 `@param`/`@return`） | Java `/** @param id 用户ID @return 用户信息 */`        |
| 私有方法 / 内部函数              | 文档注释或单行注释                  | `/** 将 DTO 转为 VO */` 或 `// 转换 DTO → VO`          |
| 字段 / 属性 / 属性，含义不直观       | 行尾注释或文档注释                  | `private final Rule rule; // 风控规则引擎`             |
| 常量 / 魔法数字（禁止魔数，但值承载业务含义） | 行尾注释                       | `private static final int MAX = 5; // 最多失败次数`    |
| 复杂算法 / 多步业务逻辑            | 独立行块注释（步骤化）                | 见 §3.1.4 模板                                      |
| 分支 / 条件判断（非显而易见）         | 单行注释                       | `// 只有管理员才允许踢人下线`                                |
| 空实现的兜底 / 预留扩展点           | 单行注释                       | `// 预留：后续接入审计日志`                                 |
| 临时注释掉的代码块                | 块注释 + 说明                   | `/* 已废弃：改用 Redis 分布式锁，见 commit xxxx */`          |
| 待办 / 已知问题                | 标签注释                       | `// TODO: 分页最大 size 应配置化`                        |
| 配置项含义（YAML/XML）          | 行尾注释                       | `# 允许同账号并发登录`                                    |
| 配置分组（YAML）               | 单行注释                       | `# ============ 前端缓存（Caffeine） ============`     |
| 模板区块（HTML/Vue/SCSS）      | 单行块注释                      | `<!-- 登录卡片 -->`、`/* 侧边栏样式 */`                    |
| 组件 / 插槽 / 复杂结构           | 块注释                        | `<!-- 文章列表：卡片式布局，支持分页 -->`                       |
| SQL 语句 / MyBatis XML 映射  | 单行注释或块注释                   | `-- 分页查询用户列表`                                    |
| 依赖 / Maven 坐标分组          | 块注释                        | `<!-- 缓存与锁 -->`                                  |
| 环境变量 / 占位符               | 行尾注释                       | `@Value("${NACOS_ADDR:127.0.0.1:8848}") // 默认本地` |

### 2.3 注释放置位置（重要！）

| 位置              | 规则                                  |
|-----------------|-------------------------------------|
| **注释在代码上方**     | 方法、逻辑块、配置项注释**一律放在上方**，**禁止**放在代码下方 |
| **行尾注释与代码间空一格** | `// 注释` 前空一格；YAML 同理                |
| **注释与代码对齐**     | 行尾注释尽量对齐（同一缩进级别），避免长短参差             |
| **注释不能与代码重叠**   | 禁止 `code//注释`（无空格）；禁止注释行与代码行挤在一起    |
| **空行分隔**        | 块注释与上方代码之间通常空一行；行尾注释不空行             |

## 3. 各语言详细规范

### 3.1 Java（后端，`spring-cloud-alibaba/`）

> 约束：遵守阿里巴巴 Java 开发规范（泰山版）。规范核心：**类、方法、属性必须用 Javadoc（`/** */`），禁止用 `//` 作为类/方法/属性的正式注释
**；方法内业务逻辑用 `//`。

#### 3.1.1 类 / 接口 / 枚举 / 注解注释

```java
/**
 * 认证中心服务：负责验证码校验、账号登录、注册、登出与踢人下线。
 *
 * <p>安全要求：登录失败统一返回"用户名或密码错误"，不区分用户是否存在，
 * 防止账号枚举（Account Enumeration）攻击。</p>
 *
 * @author xytang
 * @since 1.0-SNAPSHOT
 */
public interface AuthService {
```

要求：

- 类注释**必须**包含：类职责一句话说明 + 可选的补充说明（安全约束、使用前提、与哪些类协作）。
- 接口/抽象类注释开头**必须**写"接口/抽象类"字样，说明其扩展点。
- 枚举注释**必须**说明每个枚举值的含义（见 3.1.4）。
- **禁止**写 `@author` 之外的实现细节换行；`@since` 可省略。

#### 3.1.2 方法注释（Javadoc）

```java
/**
 * 账号密码登录，成功返回访问令牌与刷新令牌。
 *
 * @param dto 登录入参（账号、密码、验证码、设备标识）
 * @param ip  客户端真实 IP（用于风控与异地登录告警）
 * @param ua  User-Agent（用于设备类型识别）
 * @return 登录结果（accessToken + refreshToken + 用户信息）
 * @throws AuthException      当账号或密码错误时抛出
 * @throws LoginLockedException 当登录失败次数达到上限被锁定
 */
R<LoginVO> login(LoginDTO dto, String ip, String ua);
```

要求：

- 公开方法**必须**写 Javadoc，含 `@param`、`@return`、`@throws`（编号与签名一一对应）。
- 方法一句话说明**必须以动词开头**，如"查询""计算""校验""构建"。
- 无返回值方法可省略 `@return`；无异常抛出可省略 `@throws`。
- 私有方法用简版 Javadoc 或 `//` 均可，但**必须**说明意图。

#### 3.1.3 字段 / 常量注释

```java
/** 读取服务（Redis 缓存） */
private final RedisService redisService;

/** 登录失败最大次数（超过则锁定） */
private static final int MAX_FAIL_COUNT = 5;

/** 业务缓存 Key 前缀：config:{key} */
private static final String CACHE_KEY_PREFIX = "config:";
```

要求：

- 字段含义不直观（如非 String/int 的魔法含义）**必须**注释。
- **禁止魔法数字**：常量必须命名 + 注释说明业务含义。
- 自解释字段（如 `private final UserMapper userMapper;`）可不加注释。

#### 3.1.4 复杂逻辑 / 算法 / 分支注释

```java
public boolean evaluateRisk(String ip, String username) {
    // 1. 登录失败计数检查：超过 5 次锁定 15 分钟
    if (loginRiskService.isLocked(username)) {
        throw new LoginLockedException();
    }
    // 2. IP 黑名单拦截：命中直接拒绝，不落计数
    if (loginRiskService.isBlacklisted(ip)) {
        throw new AuthException(BizCode.IP_BLACKLISTED);
    }
    // 3. 异地登录告警：与上次登录 IP 对比，跨省则不阻断仅告警
    if (loginRiskService.isAbnormalLocation(ip, username)) {
        log.warn("异地登录告警：user={}, ip={}", username, ip);
    }
    return true;
}
```

要求：

- 多步逻辑**必须**用 `// 1.`、`// 2.`、`// 3.` 编号步骤，注释说明**每步的意图**。
- 分支注释**必须**说明该分支的触发条件与处理结果。
- 若某步逻辑 <= 2 行且自解释，可省略该步注释。

#### 3.1.5 枚举注释

```java
/**
 * 登录设备类型。
 *
 * @see com.xytang.auth.enums.DeviceTypeEnum
 */
public enum LoginTypeEnum {
    /** 账号密码登录 */
    PASSWORD,
    /** 短信验证码登录 */
    SMS,
    /** 邮箱验证码登录 */
    EMAIL,
    /** 扫码登录 */
    QRCODE
}
```

要求：每个枚举值**必须**有 `/** 中文说明 */`，说明该值适用场景。

#### 3.1.6 注解使用处的注释（可选，但推荐）

```java

@DistributedLock(key = "auth:login:fail:{#username}", waitTime = 2) // 防并发登录失败计数丢失
public void recordLoginFail(String username) {
    ...
}
```

#### 3.1.7 阿里巴巴规范要点（强制）

1. 类、方法、属性**必须**用 Javadoc（`/** */`），禁止用 `//` 冒充当正式注释。
2. 抽象方法（含接口方法）**必须**有 Javadoc。
3. 注释**不得**放在代码下方或代码中间插入。
4. 注释掉的代码**必须**上方注明原因，如 `// 已废弃：旧版校验逻辑，改用 @Validated 注解校验`。
5. **禁止** `// FIXME`/`// TODO` 遗留不处理；如必须遗留，须注明负责人与截止时间。
6. 注释中**禁止**出现 `System.out`、`e.printStackTrace()` 等调试输出。

### 3.2 TypeScript / JavaScript（前端，`vue-web-ui/`）

> 约束：使用 JSDoc 风格（`/** */`），与 `@sca/types`、`@sca/api` 共享类型保持一致。

#### 3.2.1 类型 / 接口 / 枚举注释

```typescript
/**
 * 文章分页查询出参。
 * @description records 中的 id 为雪花 ID 字符串，禁止转为 number
 */
export interface ArticlePageVO {
    /** 文章列表 */
    records: ArticleVO[]
    /** 总条数 */
    total: number
    /** 当前页码（从 1 开始） */
    page: number

    size: number
```

要求：接口/类型**必须**注释；字段含义不直观的**必须**加 `/** */`。

#### 3.2.2 函数 / 组合式函数注释

```typescript
/**
 * 监听文章标题元素，计算当前阅读章节。
 *
 * 通过 IntersectionObserver 观察标题元素，离开窗口时兜底重算，

 *

 * @returns 当前激活的标题 id（响应式 ref）
 */
export function useArticleToc(toc: Ref<TocItem[]>) {
```

要求：

- 导出函数 / 组合式函数**必须**写 JSDoc，含 `@param`、`@returns`。
- 说明函数**做了什么**以及**为什么这样实现**（如使用 IntersectionObserver 的原因）。
- 内部（未导出）函数可简写为 `/** 计算当前高亮章节 */` 或 `//`。

#### 3.2.3 常量 / 魔法值注释

```typescript
/** 滚动高亮检测区域：视口纵向 20%~30% 的窄窗口 */
const ROOT_MARGIN = '-20% 0px -70% 0px'

/** 验证码有效期：5 分钟 */
const CAPTCHA_TTL = 5 * 60 * 1000
```

#### 3.2.4 复杂逻辑注释

与 Java 相同：用 `// 1.`、`// 2.` 编号步骤，说明步骤意图。

```typescript
async function submitLogin() {
    // 1. 前端校验：账号/密码/验证码非空
    if (!loginForm.account) { ...
    }
    // 2. 调用登录接口，成功后跳转 redirect 参数指向的页面
    await userStore.loginByAccount({...})
    // 3. 失败时刷新验证码，避免用户重复输入已失效的验证码
catch
    {
        await loadCaptcha()
    }
}
```

#### 3.2.5 特殊约定

- **禁止**为 `import` 语句添加注释（除非导入别名有特殊含义）。
- **禁止**为 `await` 调用链写逐行注释，只需在关键步骤上注释。
- 正则表达式**必须**注释其匹配规则：`const PHONE_PATTERN = /^1[3-9]\d{9}$/ // 中国大陆手机号`

### 3.3 Vue 单文件组件（`*.vue`）

> 约束：结构必须为 `<template>` → `<script setup>` → `<style>`，注释按各块分别遵循 HTML / TS / CSS 规范。

#### 3.3.1 组件顶部注释（放在 `<script setup>` 第一行）

```vue
<script setup lang="ts">
/**
 * 登录/注册二合一卡片页面。
 * - 登录态：账号 + 密码 + 图形验证码
 * - 注册态：账号 + 密码 + 确认密码，注册成功自动登录
 * 通过 URL 参数 ?mode=register 可直接切换到注册态。
 */
```

要求：每个页面/组件**必须**有一句组件职责说明 + 可选的补充说明（数据流、交互、依赖）。

#### 3.3.2 `<template>` 中区块注释

```html

<template>
    <div class="login-page">
        <div class="login-card">
            <!-- 登录态卡片：账号/密码/验证码表单 -->
            <template v-if="mode === 'login'">
                ...
            </template>

            <!-- 注册态卡片：账号/密码/确认密码表单 -->
            <template v-else>
                ...
            </template>
        </div>
    </div>
</template>
```

要求：

- 页面中**每个独立区块**（`v-if`/`v-if-else`/`v-for`/`slot`）用 `<!-- 区块说明 -->` 标注。
- 可复用组件标签处**必须**注释其用途：`<!-- 顶部导航栏，含搜索与用户菜单 -->`。
- 复杂绑定（如 `:style`、`@click` 带复杂逻辑）**必须**行尾注释说明。

#### 3.3.3 `<script setup>` 中注释

遵循 §3.2 TypeScript 规范。组合式函数调用处可加注释说明用途：

```typescript
const {activeId} = useArticleToc(toc) // 监听标题滚动，联动右侧目录高亮
```

#### 3.3.4 `<style scoped>` 中注释

遵循 §3.5 CSS/SCSS 规范。scoped 样式**必须**按区块注释：

```css

.login-page {
    ...
}

/* 登录卡片：白底圆角 + 阴影 */
.login-card {
    ...
}

<
/
style >
```

### 3.4 HTML（`index.html`、`*.html` 模板）

| 位置      | 注释示例                                      | 要求             |
|---------|-------------------------------------------|----------------|
| 文件顶部    | `<!-- ============ 博客首页 ============ -->` | 说明页面用途         |
| 区块      | `<!-- 顶栏：导航 + 搜索 -->`                     | 每个语义区块**必须**标注 |
| 脚本/样式引入 | `<!-- 引入依赖：echarts 图表库 -->`               | 说明第三方资源用途      |
| 表单/列表   | `<!-- 用户列表：分页表格，支持搜索/编辑/删除 -->`           | 说明数据与交互        |

### 3.5 CSS / SCSS / SASS（`*.css`、`*.scss`、`*.sass`）

> 约定：SCSS 建议用 `//` 单行注释（编译时被剔除），编译产物保留的用 `/* */`。

| 场景        | 注释示例                                      | 说明              |
|-----------|-------------------------------------------|-----------------|
| 文件/区块头    | `/* ============ 侧边栏样式 ============ */`   | 说明区块职责          |
| 类选择器      | `/* 侧边栏折叠按钮 */` `.collapse-btn { ... }`   | 每个非自解释类**必须**注释 |
| 变量        | `// 主色：品牌蓝` `$primary-color: #2563eb;`    | 说明变量语义          |
| Mixin/函数  | `/// 文本省略号截断` `@mixin ellipsis() { ... }` | 说明用途与参数         |
| hack / 兼容 | `/* IE11 不支持 gap，退回 margin */`            | 说明非标准写法原因       |
| 动画        | `/* 呼吸灯：用于在线状态提示 */`                      | 说明动画效果          |

**禁止**：为 `margin: 0`、`padding: 0` 等重置类写注释。

```sql
-- 创建用户表：支持逻辑删除与雪花 ID 主键
CREATE TABLE sys_user
(
    id          BIGINT PRIMARY KEY COMMENT '雪花 ID',
    username    VARCHAR(50)  NOT NULL UNIQUE COMMENT '登录账号（唯一）',
    password    VARCHAR(100) NOT NULL COMMENT 'Argon2id 哈希（含盐与参数）',
```

- 每个表/索引/视图**必须**有 `-- 说明` 注释。

## 4. 注释写入规则（AI 生成时的动作指引）

### 4.1 必须写（Mandatory）

1. 公开类、接口、枚举、方法、函数、类型、配置项
2. 非自解释的字段、常量、魔法值、正则、占位符
3. 复杂算法、多步业务逻辑、非显而易见的分支条件
4. 模板/页面的区块边界（HTML、Vue、SCSS）
5. 安全敏感代码（密码哈希、Token 校验、越权拦截）的**安全约束说明**
6. 框架集成点（Spring 配置类、Sa-Token 过滤器、Vue 守卫）的**「为什么这样集成」说明**

### 4.2 应当写（Recommended）

1. 私有方法、内部函数的意图
2. 临时处理、Workaround、预留扩展点
3. 与外部系统/第三方服务的交互方式
4. 性能敏感点（如循环内查询、缓存穿透）的优化说明

### 4.3 禁止写（Forbidden）

1. **废话注释**：`// 声明变量`、`// 循环遍历`、`// 调用方法`
2. **重复代码注释**：与代码一一对应的翻译式注释
3. **过时注释**：与当前代码不一致的注释（生成前必须核对）
4. **敏感信息**：密码、Token、密钥、身份证号、真实 IP（注释中同样禁止）
5. **情绪化注释**：`// 这里很奇怪`、`// 别碰这段代码`、`// 我自己都看不懂`
6. **大段复制注释**：把方法体复制到注释里
7. **注释中写代码**：注释里贴大段代码（除非是 ASCII 图/示例）
8. **不必要的版权头**：仅在确实需要时添加（本项目不强制）

### 4.4 修改代码时同步更新注释

- AI 修改任何代码时，**必须**检查并更新受影响的注释（删除失效注释、修正过期描述）。
- 删除代码时，**必须**删除其专属注释，避免残留"孤儿注释"。
- 重命名变量/方法时，**必须**同步更新所有引用它的注释。

## 5. AI Agent 生成注释的标准流程

> 当 AI 被要求"为某文件/某模块补充注释"时，按以下流程执行：

### 步骤 1：阅读上下文

1. 读取仓库根 `CLAUDE.md` 与对应子项目 `CLAUDE.md`，确认工程约束。
2. 读取目标文件及其实体全部内容（禁止只读一半）。
3. 若涉及跨模块，阅读调用方/被调方相关代码，理解**数据流与调用链**。

### 步骤 2：分析注释策略

1. 先整理文件中的**公开成员清单**（类、方法、字段、配置项）。
2. 区分"必须写"与"应当写"的注释点（见 §4）。
3. 识别复杂逻辑块，规划步骤化注释（`// 1.`、`// 2.`...）。

### 步骤 3：编写注释

1. 按 §3 各语言规范逐条编写。
2. 注释语言用简体中文，术语保留英文原文。
3. 注释**必须**表达 Why，**禁止**翻译代码。

### 步骤 4：自检验证

按 §6 检查清单逐项核对，全部通过后才算完成。

### 步骤 5：提交

- 遵循 Conventional Commits，type 用 `docs`：`docs(注释): 为 spring-cloud-auth 登录流程补充 Javadoc`。
- **禁止**与代码改动混在一个 commit（除非是同一改动的一部分）。
