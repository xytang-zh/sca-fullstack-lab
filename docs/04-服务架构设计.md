## 4.2 后端服务拆分（11 个服务 + 1 个网关 + 1 个认证中心）

| # | 服务名                     | 端口 | 类型 | 主要职责 |
|---|-------------------------|------|------|----------|
| 0 | `spring-cloud-gateway`  | 8080 | 网关 | 路由、限流、鉴权、日志 |
| 1 | `spring-cloud-auth`     | 8081 | 认证中心 | Sa-Token SSO Server、登录、踢人下线、OAuth2 |
| 2 | `spring-cloud-system`   | 8082 | 业务 | 用户、角色、菜单、字典、参数、部门、岗位 |

| 5 | `spring-cloud-ai`       | 8085 | 业务 | Spring AI + RAG、对话、知识库 |
| 6 | `spring-cloud-message`  | 8086 | 基础设施 | RabbitMQ 消息总线、WebSocket 推送、站内信 |
| 7 | `spring-cloud-search`   | 8087 | 基础设施 | ElasticSearch 全文检索 |
| 8 | `spring-cloud-file`     | 8088 | 基础设施 | MinIO 文件上传、分片、断点续传 |
| 9 | `spring-cloud-log`      | 8089 | 基础设施 | 操作日志、登录日志、审计（MongoDB） |
| 10 | `spring-cloud-portal`   | 8090 | 业务 | 公开门户（SEO/GEO、博客、新闻） |
| 11 | `spring-cloud-job`      | 8091 | 基础设施 | 定时任务调度（**XXL-JOB 执行器**，admin 独立部署） |

> **Netty WebSocket 端口**：9090（monitor）、9091（message）
> **XXL-JOB Admin 端口**：8080（与 Gateway 同端口冲突，改为 8099）
> **XXL-JOB 执行器端口**：9999 起，每服务 +1

## 4.4 各服务详细职责

### 4.4.1 spring-cloud-gateway（网关）

**核心职责**：
1. **路由转发**：`/api/system/**` → spring-cloud-system，`/api/ai/**` → spring-cloud-ai ...
2. **统一鉴权**：基于 Sa-Token，校验 Token、解析 loginId、放入请求头透传
3. **限流熔断**：集成 Sentinel，按路由维度配置限流规则
4. **跨域处理**：CORS 全局配置
5. **日志记录**：请求/响应日志、慢请求标记
6. **灰度发布**：基于请求头/版本的灰度路由

**关键依赖**：
- `spring-cloud-starter-gateway`
- `spring-cloud-starter-alibaba-sentinel`
- `sa-token-spring-cloud3-gateway`（社区适配）

**关键代码骨架**：

```java
@Configuration
public class SaTokenRouteFilterFactory extends AbstractGatewayFilterFactory<Object> {
    @Override
    public GatewayFilter apply(Object config) {
        return (exchange, chain) -> {
            ServerHttpRequest req = exchange.getRequest();
            // 1. 校验 Token
            SaTokenContext context = ...;
            Object loginId = StpUtil.getLoginIdByToken(token);
            if (loginId == null) return unauthorized(exchange);
            // 2. 透传 loginId
            req.mutate().header("X-Login-Id", loginId.toString()).build();
            return chain.filter(exchange);
        };
    }
}
```

### 4.4.2 spring-cloud-auth（认证中心 / SSO Server）

**核心职责**：
1. **登录认证**：账号密码、手机短信、邮箱验证码、扫码登录
2. **SSO Server**：发放授权码、校验 Client、生成 Token
3. **踢人下线**：基于 Sa-Token 的 `kickout` API
4. **OAuth2 Server**：授权码模式、客户端凭证模式
5. **会话治理**：在线用户列表、强制注销、Token 续期

**关键依赖**：
- `sa-token-spring-boot3-starter`
- `sa-token-sso`
- `sa-token-oauth2`

**关键接口**：
- `POST /sso/login`：登录入口
- `POST /sso/logout`：全端注销
- `GET /sso/users`：在线用户列表
- `POST /sso/kickout`：踢人下线
- `POST /oauth2/authorize`：OAuth2 授权
- `POST /oauth2/token`：OAuth2 颁发 Token

### 4.4.3 spring-cloud-system（系统管理）

**核心职责**：

| 子模块 | 功能 |
|--------|------|
| 用户管理 | 用户 CRUD、重置密码、启用/禁用、分配角色 |
| 角色管理 | 角色 CRUD、分配菜单、数据权限 |
| 菜单管理 | 菜单树、按钮权限、路由元数据 |
| 部门管理 | 部门树、数据权限范围 |
| 岗位管理 | 岗位 CRUD |
| 字典管理 | 字典类型、字典数据 |
| 参数管理 | 系统参数配置（含 Nacos 配置） |
| 通知公告 | 通知发布、已读未读 |
| 在线用户 | 在线列表、强制下线（调 auth-center） |

**关键表**：
- `sys_user`、`sys_role`、`sys_menu`、`sys_dept`、`sys_post`
- `sys_user_role`、`sys_role_menu`、`sys_role_dept`
- `sys_dict_type`、`sys_dict_data`、`sys_config`
- `sys_notice`、`sys_notice_read`

**关键依赖**：
- `mybatis-plus-spring-boot3-starter`
- `dynamic-datasource-spring-boot3-starter`
- `spring-cloud-common-satoken`

### 4.4.4 spring-cloud-monitor（服务器监控）

**核心职责**：
1. **指标采集**：CPU、内存、磁盘、网络、JVM、线程
2. **存储**：TDengine 时序库（一台机器一个超级表）
3. **推送**：Netty WebSocket 实时推送
4. **告警**：阈值告警（CPU > 80%）→ RabbitMQ → 站内信
5. **历史查询**：1h / 24h / 7d 历史曲线

**采集方式**：
- 服务端用 `OSHI`（Java 系统信息库）采集
- 每个 spring-cloud-* 微服务内置 monitor-agent 上报
- monitor-service 聚合 + 入库 + 推送

**关键表（TDengine）**：
```sql
-- 超级表
CREATE STABLE metrics (
    cpu_usage DOUBLE,
    mem_usage DOUBLE,
    disk_usage DOUBLE,
    jvm_heap DOUBLE,
    jvm_non_heap DOUBLE,
    thread_count INT
) TAGS (service_name VARCHAR(64), instance VARCHAR(128));
```

**关键依赖**：
- `taos-jdbcdriver`（TDengine JDBC）
- `org.dromara.warm:warm-flow-mybatis-plus-sb3-starter`（被 workflow 用，这里不用）
- `netty-all`
- `oshi-core`

### 4.4.5 spring-cloud-workflow（工作流）

**核心职责**：
1. **流程定义**：导入 JSON、可视化设计器、发布、停用
2. **流程实例**：发起、催办、撤销
3. **任务处理**：审批、驳回、转办、委托、加签
4. **历史查询**：已办、待办、流程实例历史
5. **业务对接**：通过 `business_id` 与业务表关联

**典型流程（4 个）**：
1. **请假流程**：申请人 → 直属领导 → HR → 归档
2. **报销流程**：申请人 → 部门经理 → 财务 → 出纳
3. **合同审批**：起草 → 法务 → 总监 → 总经理
4. **采购申请**：申请人 → 部门 → 采购 → 财务

**关键依赖**：
- `org.dromara.warm:warm-flow-mybatis-plus-sb3-starter:1.8.8`

### 4.4.6 spring-cloud-ai（AI 助手）

**核心职责**：
1. **文档管理**：上传 PDF/Markdown/TXT（存 MongoDB）
2. **文档处理**：分块（TokenTextSplitter）、向量化（EmbeddingModel）、入 pgvector
3. **对话**：ChatClient + QuestionAnswerAdvisor + MemoryAdvisor
4. **流式响应**：SSE 推送 token
5. **对话历史**：MongoDB 存对话，按 sessionId 分组
6. **知识库管理**：知识库 CRUD、文档增删改查、重建索引

**数据流**：

```
用户上传文档 → MongoDB（原文件）
                ↓
        分块 + Embedding
                ↓
        pgvector（向量库）
                ↓
用户提问 → 向量检索 Top-K → 拼接上下文 → LLM 生成 → SSE 推回
                ↓
        MongoDB（对话历史）
```

**关键依赖**：
- `spring-ai-openai-spring-boot-starter` 或 `spring-ai-alibaba`
- `spring-ai-pgvector-store-spring-boot-starter`
- `spring-ai-vector-store-advisor`

### 4.4.7 spring-cloud-message（消息中心）

**核心职责**：
1. **MQ 消费**：消费 RabbitMQ 事件（任务待办、告警、系统通知）
2. **WebSocket 推送**：Netty Server，按 userId/channel 推送
3. **站内信**：CRUD + 已读未读
4. **邮件**：基于 spring-boot-starter-mail
5. **短信**：预留接口（阿里云/腾讯云）

**关键设计**：
- Netty Server 与 Spring Boot 同进程，端口 9091
- 前端建立 WebSocket 连接后，注册 `userId → Channel` 映射
- MQ 消费到消息 → 查 Channel → push

**关键依赖**：
- `spring-boot-starter-amqp`
- `netty-all`
- `spring-boot-starter-mail`

### 4.4.8 spring-cloud-search（全文检索）

**核心职责**：
1. **索引管理**：创建索引、Mapping、删除
2. **数据同步**：MySQL → ES（基于 MQ 增量 + 定时全量）
3. **搜索**：文章、知识库、日志、用户等多维度搜索
4. **高亮**：搜索结果高亮关键词

**关键依赖**：
- `spring-boot-starter-data-elasticsearch` 或 Elasticsearch Java Client 8.x

### 4.4.9 spring-cloud-file（文件服务）

**核心职责**：
1. **上传**：单文件、批量、分片上传
2. **下载**：普通下载、断点续传
3. **预览**：图片、PDF、Office（KKFileView 集成）
4. **管理**：文件 CRUD、回收站、配额管理
5. **预签名 URL**：前端直传 MinIO

**关键依赖**：
- `minio` Java SDK
- Spring Boot Web

### 4.4.10 spring-cloud-log（日志服务）

**核心职责**：
1. **操作日志**：基于 AOP + 注解，记录接口调用
2. **登录日志**：登录成功/失败记录
3. **审计日志**：敏感操作记录（删除、修改权限）
4. **存储**：MongoDB（适合写入多、查询少场景）

**关键设计**：
- `@OperationLog` 注解 + AOP 切面
- 异步发送到 RabbitMQ → log-service 消费入库

### 4.4.11 spring-cloud-portal（公开门户）

**核心职责**：
1. **博客**：文章 CRUD、Markdown 编辑、标签、分类
2. **新闻**：新闻发布、栏目管理
3. **产品介绍**：产品 CRUD
4. **SEO**：Sitemap、Meta 标签、结构化数据
5. **GEO**：地理位置相关内容（如本地服务）

**关键设计**：
- 前端用 Vite SSG（Static Site Generation）做静态化
- 后端只提供 API，前端构建时预渲染

### 4.4.12 spring-cloud-job（定时任务执行器 / XXL-JOB Executor）

**核心职责**：
1. **任务执行器**：集成 `xxl-job-core:3.5.0`，注册到 XXL-JOB Admin
2. **任务实现**：所有微服务的定时任务 handler 都集中在本服务（或散布在各服务）
3. **典型任务**：
   - 监控指标聚合（每分钟从 monitor 取最新 → 写 Redis 缓存）
   - AI 对话历史归档（每天凌晨把 MongoDB 对话 → ES）
   - 文章全量同步到 ES（每天凌晨 2 点）
   - 流程实例超时催办（每 10 分钟扫描）
   - 操作日志清理（每天凌晨清理 30 天前）

**部署模式**：
- XXL-JOB Admin 独立容器（见 07 章 docker-compose）
- spring-cloud-job 是一个执行器，也可以让所有业务服务自带执行器（推荐）

**关键依赖**：

```xml
<dependency>
    <groupId>com.xuxueli</groupId>
    <artifactId>xxl-job-core</artifactId>
    <version>3.5.0</version>
</dependency>
```

**关键代码**：

```java
@Component
public class SyncArticleJob {
    @XxlJob("syncArticleToEs")
    public void execute() {
        XxlJobHelper.log("开始同步文章到 ES...");
        articleService.syncToEs();
        XxlJobHelper.handleSuccess("同步完成");
    }
}
```

### 4.4.13 spring-cloud-report（低代码报表 / JimuReport）

**核心职责**：
1. **报表设计器**：嵌入 JimuReport，提供 `/jmreport/*` 入口
2. **数据源管理**：复用 dynamic-datasource 配置的 MySQL / PG / 国产库
3. **典型报表**：
   - 用户增长曲线（按日 / 周 / 月）
   - 订单统计报表（分组汇总）
   - 工作流审批时长分析
   - 服务器监控大屏（数据源接 TDengine）
   - AI 对话量趋势（数据源接 MongoDB）
4. **导出能力**：Excel / PDF / 大屏截图
5. **打印**：浏览器打印 + 服务端打印

**Maven 依赖**：

**配置**：


**鉴权集成**：

- 进入 `/jmreport/list` 前需 Sa-Token 校验 + 角色判断（仅 ADMIN 可访问）

### 4.4.14 分表场景（ShardingSphere）
